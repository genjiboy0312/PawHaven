# Crumbling Platforms Survival

## 사용자 승인 범위
- 싱글: 30초 생존 성공, 낙하 시 재도전 또는 로비 복귀.
- 멀티: 최대 4명, 최대 60초, 마지막 생존자 승리. 제한 시간까지 남은 참가자는 공동 우승. 탈락자는 같은 맵을 관전한다.
- 한 화면의 6개 발판을 사용한다. 기존 하늘·잔디·흙·동물 아틀라스·장착 레이어·이동/점프/대시·카운트다운·결과 팝업을 재사용한다. 공격과 완주 진행률은 이 모드에서 숨긴다.
- 맵 선택의 `무너지는 발판 / Crumbling Platforms`로 진입한다. 프로토타입에는 코인·경험치·퀘스트 보상을 지급하지 않으며, 기존 달리기 기록/목표에 포함하지 않는다.

## 구조와 규칙
- `SurvivalArena`의 순수 시간 함수로 안전 → 경고 → 사라짐 → 복구를 계산한다. 3초 준비 후 5.2초 주기(안전 2.4초, 경고 1.6초, 사라짐 1.2초). 경고 대상이 2개 → 3개 → 4개로 증가하며 항상 안전한 발판이 남는다.
- `SurvivalRound`가 생존 상태와 발판 충돌 상태를 담당한다. `DummyRun`은 기존 물리·점프 버퍼·코요테 타임·지상 대시를 재사용하며, 이 모드에서만 피니시 판정/낙하 후 체크포인트 복귀를 하지 않는다.
- 씬별로 발판 상태를 복사하여 공유 원본과 다른 플레이를 변경하지 않는다. `CourseTerrain`과 `SurvivalPlatformsView`가 기존 타일 경계와 경고 표시를 그린다. 화면 효과 OFF에서는 경고색과 기호를 유지하고 깜빡임만 끈다.
- 싱글은 기존 일시정지/앱 복귀/재시작/로비 확인 흐름을 사용한다. 종료 상태에서 재시작 실패 시 안내와 버튼 복구도 유지한다.
- 멀티는 기존 loaded 장벽과 서버 startsAt 기준의 경과 시간으로 발판을 맞춘다. 관전자도 공통 시간으로 발판을 계속 갱신한다. 결과 시간과 발판은 서버 결과에 맞춰 고정한다.
- 클라이언트는 자기 낙하만 `eliminate`로 보고한다. 서버는 참가자·라운드·진행 상태·낙하 높이를 검사하고 서버 시각으로 탈락 시간을 한 번 기록한다. 같은 요청을 반복해도 탈락 시간이 늘어나지 않는다.
- 서버가 마지막 생존자/제한 시간/연결 종료를 처리한다. 결과 팝업은 승자 우선, 생존 시간 내림차순으로 표시하며 공동 우승을 표현한다. 기존 레이스는 시간 오름차순을 유지한다.
- 이 프로토타입은 클라이언트가 낙하를 보고하는 구조이며 서버에서 전체 물리를 시뮬레이션하는 부정행위 방지 서버는 아니다. 보상 경쟁/랭킹을 연결하기 전 별도 설계가 필요하다.

- 선행: `Social Account Level Labels`(035). 기존 멀티 방·계정 레벨·초대 전용·착용 검증을 유지하며 멀티 맵과 탈락 필드를 확장한다. 새 경제 테이블/보상은 만들지 않는다.
- `survivalReady` 응답이 없는 서버에는 새 모드 생성/맵 변경 요청을 보내지 않고 UI에서 선택을 비활성화한다.
- 사용자 SQL 실행 성공 확인 완료. 로컬 DB에서 재실행·기존 레이스 완주·권한·보상 엔드포인트 거부를 검증했다.

- 순수 물리: 준비 구간, 결정적 발판 패턴, 낙하 탈락/무부활, 피니시 오작동 방지, 30초 성공, 늦게 들어온 시간 보정, 원본 타일 비변경.
- 실제 로컬 PostgreSQL(PGlite): loaded 공통 시작, 60초 제한, 타인 탈락 방지, 중복·과거 라운드·잘못된 높이 거부, 관전 유지, 최후 생존자, 공동 우승/접속 종료, SQL 재실행, 기존 보상 경로로 새 모드 보상 획득 불가.
- Chrome에서 실제 Game/리소스로 싱글 선택→경고→패배→재시작→30초 성공과 모바일 가로 화면을 확인했다. 두 Chrome 컨텍스트를 로컬 DB에 연결해 탈락 전파·관전·상대 숨김·동일 승자/이모션 결과를 확인했다.
- 운영 Supabase의 실제 두 계정·모바일 네트워크 지연 검증과 구분한다. 로컬 브라우저 검사는 테스트용 이동/탈락을 제어했다. 조작 난이도는 사용자 실플레이 후 조정한다.

## 2026-11-07 게임 종류별 맵 선택
- 기존 맵 선택창에 레이스/서바이벌 필터를 추가했다. `CourseCatalog.mode`를 공통 분류로 사용하고, `GameModeTabs`가 게임 종류 버튼·선택 상태·목표 안내를 공유한다.
- 싱글 맵 선택과 방장의 맵 선택 팝업은 현재 선택된 맵의 게임 종류로 열린다. 탭 탐색만으로 선택 맵/서버 방 상태를 바꾸지 않고, 맵 카드를 누를 때 반영한다. 취소 후 재진입은 실제 선택 맵 기준으로 복원한다.
- 방 만들기도 같은 컴포넌트를 사용한다. 종류 변경 시 해당 종류의 첫 멀티 지원 맵을 생성 예정 값으로 선택하고 입력한 방 제목은 유지한다. 서버 요청은 방 생성 버튼을 누를 때만 전송한다.
- 구형 서버에서 서바이벌 카드는 비활성화하고 생성 버튼도 차단한다. 레이스의 싱글 전용 맵은 멀티 목록에 포함하지 않는다. 방장 전용 맵 변경·준비 초기화·공통 시작 규칙은 유지한다.
- 방 목록과 대기방 미리보기에 같은 게임 종류 배지를 표시한다. 기존 PNG 표면과 Jua 폰트를 사용하며 한영 전환을 지원한다. 목표 안내는 '먼저 도착하기 / 끝까지 살아남기'로 짧게 표시한다.
- 모바일에서 게임 종류 버튼 아래 카드 전체를 볼 수 있도록 기존 팝업 높이를 90%로 맞추고 간격·중복 설명을 줄였다. 목록 스크롤과 닫기/포커스 복구를 유지한다.
- 새 이미지·SQL·패키지 없음. 관련 멀티/기록 검사 103개 통과, 최종 멀티/서바이벌 검사 102개와 타입 검사·빌드 재통과.
- 실제 Chrome에서 싱글·방 생성·방장 맵 변경·방 목록 배지, 제목 보존, 선택 전 RPC 미전송, 한영/Jua와 844×390 카드 전체 표시·가로 넘침 없음을 검증했다. 서버 전송은 테스트용 transport를 사용했으며 운영 다계정 검증과 구분한다.

## 2026-11-07 계단 발판 맵
- `terraces` / 계단 발판 / Stepping Platforms를 기존 서바이벌 탭에 추가한다. 낮은 발판(0)과 높은 발판(64)을 번갈아 배치한 6칸 구조다. 최고 점프 높이 약 99보다 낮아 일반 점프로 이웃 칸을 오갈 수 있다.
- 기존 타일 폭·표면·경고·공통 시간 패턴과 낮은 칸/높은 칸 모두 one-way 충돌을 재사용한다. 위로 통과해 착지할 수 있으며 높은 칸에서 옆의 낮은 칸으로 내려온다. 준비 구간과 경고 시간, 30초/60초 생존·관전·결과 규칙은 기존 맵과 동일하다.
- 기존 아침 하늘과 잔디/흙 타일·캐릭터·조작을 재사용한다. 새 이미지·보상·패키지는 추가하지 않는다.
- 게임 흐름은 특정 맵 ID 대신 `CourseCatalog.mode`로 서바이벌 여부를 판단한다. 두 맵 모두 공격·완주 지점·코인/경험치·달리기 개인 기록/목표에서 제외한다.
- `RoomClient.canSelectMap`이 맵별 서버 지원을 검사한다. 기존 `survivalReady`는 평지 맵에 유지하고, 계단 맵은 `terracesReady`를 별도로 사용한다. 오래된 서버에서도 평지 맵은 계속 선택 가능하다.
- 서버 지원 상태 갱신 중 버튼이 잠긴 채 남는 경우를 수정했다. 방 생성 화면은 잠금 상태가 달라질 때 갱신하고, 일반 폴링 때는 입력 중인 제목을 불필요하게 재생성하지 않는다.
- SQL Editor 이름: **Terraced Survival Map**. 파일: `supabase/migrations/202611070039_terraced_survival.sql`. 038 이후 적용하며 사용자 실행 성공 확인 완료. 기존 멀티·재화·기록을 유지한다.
- SQL은 계단 맵을 기존 시작 장벽·60초 제한·탈락·최후 생존자·공동 우승에 포함한다. 기존 맵 조건과 권한·서버 시각·중복 방지 규칙은 유지한다.
- 검증: 30/60/120FPS에서 모든 인접 칸을 양방향 일반 점프로 통과했다. 관련 128개 테스트를 먼저 통과했고, 전체 회귀 검사에서 발견한 지원 상태 갱신 문제를 수정한 뒤 최종 멀티/서바이벌 테스트 107개를 통과했다. 타입 검사·프로덕션 빌드 통과.
- 로컬 DB에서 SQL 선행/재실행, 계단 맵 공통 시작·탈락·공동 우승·기존 레이스 유지·보상 엔드포인트 거부를 확인했다. Chrome 실제 Game에서 새 맵 선택, 키보드 점프/착지/내려오기, 패배/재도전/30초 성공과 보상 요청 미전송, 모바일 렌더링을 확인했다. 브라우저에서도 서버 지원 갱신 뒤 버튼 복구를 검증했다.
- 운영 Supabase 두 계정의 실시간 이동·모바일 터치 난이도는 사용자 확인 대상으로 남긴다. 로컬 성공 타이머 검사는 안전한 발판으로 위치를 제어했으며, 인접 칸 점프와 키보드 착지는 별도로 검증했다.

## 싱글 계단 발판 패턴
- 싱글 계단 발판에서 낮은 칸부터 위험해진 뒤 높은 칸과 번갈아 무너진다. 기존 3초 준비와 5.2초 주기, 경고 표시를 재사용한다.
- 한 주기에는 한 높이의 발판 3개만 무너진다. 가장자리에서도 반대 높이의 이웃 칸으로 일반 점프할 수 있다.
- 멀티 계단은 공용 기본 패턴을 사용한다. 기존 계단 맵의 개인 기록은 그대로 읽는다.
- 관련 테스트 116개를 통과했다. 30/60/120 FPS에서 경고에 맞춰 일반 점프 다섯 번으로 30초를 생존했고, 싱글과 멀티가 다른 패턴을 선택하는지 확인했다.

## 싱글 평지 발판 패턴
- 인접한 두 칸이 깜빡이다 무너진다. 붕괴 구간은 1·2번부터 5·6번까지 한 주기에 한 칸씩 오른쪽으로 진행하며, 각 주기가 끝나면 발판이 복구된다.
- 계단과 같은 경고 타이밍과 렌더러를 사용한다. 맵별 싱글 패턴은 `CourseCatalog`에서 지정하며 멀티는 공용 기본 패턴을 사용한다.
- 관련 테스트 117개를 통과했다. 30/60/120 FPS에서 첫 경고 후 출발점부터 달리기만으로 피하고, 마지막 위험 구간에서는 복구된 왼쪽 칸으로 돌아와 30초를 생존했다.
