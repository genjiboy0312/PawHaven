# 공원 프로토타입 (2026-10-24)

## 모바일 키보드·상시 대화창 (최신 사용자 수정, 이전 접이식 기획 대체)
- 전체화면 후속 보정: 화면 높이가 바뀌지 않고 키보드가 겹치는 경우를 추가로 처리한다. 지원되는 VirtualKeyboard API의 geometrychange/boundingRect로 가려진 영역을 제외하고 overlaysContent 정책은 입력 중에만 적용한 뒤 원복한다. VisualViewport 축소와 중복으로 키보드 높이를 빼지 않는다. API 미지원이면 기존 VisualViewport 경로를 사용한다.
- 입력 동안 #app의 실제 크기·중심 위치를 고정해 키보드/주소창 변화가 게임·카메라까지 재배치하지 않게 한다. CSS 회전은 유지하고 키보드 종료 시 기존 인라인 스타일과 키보드 정책을 복원한다. 전체화면을 강제로 해제하지 않는다. 채팅은 활성 fullscreen 요소 내부에 배치해 top layer 뒤에 숨지 않게 한다.
- Chrome에서 실제 requestFullscreen 진입 후 키보드 geometry/viewport를 모의해 전체화면 유지·게임 크기 고정·입력 가시성·전송 중 dock 유지·닫힘 복원·cleanup을 확인했다. 관련 자동 테스트 8개와 타입 검사/빌드 통과. 실제 모바일 OS 키보드 검증을 대체하지 않는다. API 근거: [Chrome VirtualKeyboard 문서](https://developer.chrome.com/docs/web-platform/virtual-keyboard/).
- 사용자 실기기 제보: 키보드가 하단 대화창을 가렸다. 대화 입력 / 최근 대화 버튼과 입력창 닫기 버튼은 제거했다. 대화 기록과 입력창을 항상 함께 표시한다.
- KeyboardChatDock 컴포넌트가 모바일 입력 시 기존 대화창 노드 전체를 body로 잠시 옮겨 VisualViewport의 실제 보이는 영역 하단에 배치한다. 게임 컨테이너의 회전·overflow에 잘리지 않으며 별도 대화창 복사본이나 배경 가림막을 만들지 않는다. 따라서 기록·새 메시지·초안·전송 이벤트가 그대로 유지된다.
- 키보드로 줄어든 viewport가 돌아오면 입력 포커스를 해제하고 원래 위치/스타일로 복귀한다. 전송 성공 시 입력만 비우고 키보드를 닫는다. 초안을 전송 중 바꿨거나 실패했다면 지우지 않는다. Escape는 입력을 종료하며 대화창은 숨기지 않는다. 채널 변경 성공 시 초안·이력을 초기화한다.
- installMobileViewport는 data-keyboard-chat=true 입력을 기존 별도 입력 편집기로 바꾸지 않는다. 방 제목 등 다른 입력의 기존 동작은 유지한다. 세로 접속 시 게임은 가로 회전을 유지하되 대화 입력 중에는 키보드 방향에서 원래 대화창 전체가 보이게 한다.
- 우측 상단 Settings 버튼은 기존 팝업을 재사용한다. 설정·채널 선택 전 dock을 원복하고 이동 입력을 해제한다. 퇴장 시 dock·viewport 구독·예약 프레임·타이머를 정리해 body에 UI가 남지 않는다.
- Jua와 기존 commerce 버튼 스타일을 유지했다. dock 중 입력은 16px로 표시한다. SQL 변경 없음.
- 239개 전체 테스트·타입 검사·빌드 통과. Chrome 터치 가로 1280×720 / 세로 400×800 및 PC 환경에서 키보드 viewport 축소/복원을 모의해 원본 노드 유지·키보드 위 표시·기록 실시간 갱신·초안·전송 실패/성공·원위치 복원·회전 입력 편집기 중복 없음·퇴장 정리를 확인했다. 실제 삼성 인터넷/키보드 동작은 사용자 실기기 확인이 필요하다.

## 상하 이동·카메라·폰트 후속 수정
- 사용자의 추가 요청으로 좌우 전용 이동을 상하좌우 바닥 이동으로 확장했다. 기존 LobbyMap/리소스는 그대로 1800×1100 월드에 사용한다. 캐릭터 발 좌표 x=80~1720, y=600~880을 허용해 하늘/배경 영역으로 걸어가지 못한다.
- 바닥 y와 점프 높이를 독립 관리한다. 대각선 속도를 정규화하며 키보드 WASD/방향키는 이동, Space만 점프한다. 조이스틱은 두 축을 지원하고 세로 화면의 CSS 회전도 보정한다.
- 카메라는 캐릭터의 바닥 좌표를 부드럽게 따라가고 월드 경계에서 정지한다. 점프 높이는 카메라에 반영하지 않는다. HUD·입력창은 고정하며, 동물은 바닥 y 순서로 정렬한다. 말풍선은 카메라 좌표로 화면 경계를 보정한다.
- 실시간 pose에 y를 추가했다. SQL 스키마 변경은 없다. 구버전 클라이언트의 y 없는 pose는 spawnY=720으로 읽는다. 정상적인 동일 월드 표시를 위해 모두 새 배포본으로 새로고침해야 한다.
- 모든 텍스트는 Jua로 통일한다. DOM은 공통 CSS 변수, Pixi는 GAME_FONT를 공유한다. 기준: [UI_STYLE.md](UI_STYLE.md).
- 전체 238개 테스트 통과. 실제 Chrome 1200×760, 640×440에서 상하 경계·양축 카메라·점프·송신 y·HUD 화면 포함 및 채팅 입력/기록/말풍선의 공통 폰트를 검증했다. 실서버 다계정 상하 동기화는 실기기 확인 대상이다.

## 승인 범위
- Choose Mode의 Single / Multiplayer 옆에 Park를 추가했다. 로그인·닉네임 설정 후 입장한다.
- 공원은 기존 LobbyMap / loadHome의 도트 배경·도트 바닥을 그대로 재사용한다. 신규 이미지 생성이나 경쟁 맵 제작은 하지 않는다.
- 동일 맵을 사용하는 채널 4개, 채널당 8명. 선택창은 2행 2열이며 인원/8을 표시한다. 상단에서 채널 변경·나가기를 제공한다.
- 기존 AnimalAnimationController, 착용 리소스, SpeechBubble, ActionButton 점프 및 조이스틱 이미지를 재사용한다. 현재 선택 캐릭터·모자·액세서리를 서버 저장 외형으로 표시한다. 상대 캐릭터는 기존 멀티 방향처럼 불투명도 대신 tint로 약간 어둡게 한다.
- 상하좌우 이동·점프만 제공한다. 키보드 WASD/방향키로 이동하고 Space로 점프한다. 대쉬·공격·승패·참가비·보상은 없다.
- 대화는 같은 채널의 머리 위 말풍선(6초)과 접이식 최근 대화창(30개)에 표시한다. 첫 입장의 과거 대화는 기록에만 표시하며 말풍선을 재생하지 않는다. 100자 제한·서버 2초 전송 간격을 적용한다. DOM은 textContent를 사용한다.
- 한국어/영어 UI를 연결했다. 모바일 세로 접속의 자연 방향 입력 편집기는 기존 installMobileViewport가 자동 적용된다. 한글 IME 조합 중 Enter 전송을 방지한다.

## 구조와 통신
- ParkModel: 이동/점프 계산과 수신 pose 검증. ParkClient: 구독 알림·서버 RPC·참가자별 실시간 채널 수명 관리. ParkScene: 렌더링·입력·UI. 기존 레이스 상태/퀘스트/코스 로직은 변경하지 않는다.
- 서버 park_command가 인증, 닉네임·저장 외형, 8명 제한, 채널 변경, 세션, 채팅 속도를 검증한다. 채널 간 변경/입장은 트랜잭션 잠금으로 직렬화한다. 채팅은 1시간 후 정리하며 최근 30개만 반환한다.
- 참가자/채팅 테이블 직접 접근을 금지한다. 실시간 topic은 paw-park:<channel>:<user>:<session>. 참가자는 같은 채널의 유효 참가자만 수신하며 본인 topic에만 전송한다. 기존 레이스 정책과 분리된 제한 정책을 추가했다.
- 이동은 약 80ms 간격으로 전송하며 수신 시 보간한다. 순서가 뒤집힌 seq/비정상 수치는 거절한다. 멤버·채팅은 2초 RPC로 복원하고 채팅 알림 broadcast 수신 시 즉시 조회한다. 브로드캐스트 자체의 텍스트를 신뢰하지 않고 서버 기록을 표시한다.
- 채널을 옮길 때 구독·좌표·이력·점프 상태를 초기화한다. 퇴장 시 구독·타이머·DOM·입력을 정리한다. 오래된 탭의 leave가 새 세션을 삭제하지 못한다. 비정상 종료 참가자는 45초 이후 정리한다. 장시간 백그라운드에서 복귀해 세션이 만료되면 채널을 다시 선택한다.
