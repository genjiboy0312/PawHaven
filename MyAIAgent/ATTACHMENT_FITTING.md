# 목 장식 리사이즈 컴포넌트 — 2026-10-30

## 현재 구현

`AttachmentFit.ts`에서 목 폭과 천 두께를 독립 조절한다. 원본 이미지의 부착선 양 끝을 대상 목 양 끝에 고정하고, 부착선 수직 방향의 두께만 별도로 맞춘다. 회전된 리소스에도 같은 변환을 적용한다.

- `AttachmentArt.mount.back/front`: 원본 이미지 안의 실제 부착선 양 끝. 여백·뒤쪽 면·천 끝을 포함하지 않는다.
- `AttachmentArt.depth`: 부착선에 수직인 앞쪽 천의 기준 두께. 매듭의 긴 끝을 기준으로 삼지 않는다.
- `CollarFit.x/y/width/height/rotation`: 각 프레임의 기존 목 기준에 대한 동물별 위치·폭·두께·각도.
- `CollarFit.poses`: 특정 동작의 보정값. 같은 동물의 이후 목 장식에서도 재사용한다.
- `height` 또는 `depth`가 없으면 기존 등비 계산으로 돌아가 기존 모자·나비넥타이를 유지한다.

기존 `neck`은 나비넥타이처럼 앞에 붙이는 장식, `collar`는 목 두름 장식이다. 새 동물은 목 기준을 한 번 보정해야 한다. 이 기능은 이미지에서 해부학적 목을 자동 인식하지 않는다. 기준이 없는 동물에는 임의 추정으로 출력하지 않는다.

## 게임·초상화 공통 계산

`attachmentPose`가 같은 2D 변환 행렬을 반환한다. Pixi는 `applyAttachmentPose`, DOM 초상화는 같은 행렬을 CSS matrix로 적용한다. 폭만 키울 때 높이가 같이 늘어나지 않고, 두께를 바꿀 때 목 양 끝이 움직이지 않는다. 원본 PNG는 수정하지 않는다. 비등비 변환이므로 지나친 압축은 문양도 눌리게 만든다. 실제 화면에서 적절한 두께를 확인한다.

## 사용 리소스와 검토 범위

사용자가 빨간색으로 지적한 목 뒤쪽 띠를 제거한 `Resources/Karakusa_Bandana_Front_Overlay.png`를 사용한다. 이전 `Fitted_Prototype`의 제거된 뒷면 기준점을 재사용하지 않는다. 새 부착선/두께는 `CollarFits.ts`의 `KARAKUSA_SCARF_ART`에 등록했다.

- 최신 대기 미리보기: `Resources/Karakusa_Neck_Resize_Preview.png`
- 최신 걷기 미리보기: `Resources/Karakusa_Neck_Resize_Walk.png`
- 앞면 리소스 제작 기록: [KARAKUSA_FRONT_OVERLAY.prompt.md](KARAKUSA_FRONT_OVERLAY.prompt.md)

초록 당초무늬 스카프는 상점의 꾸미기 → 장식에서 75코인으로 구매할 수 있다. 기존 장식 구매와 저장 형식(Acc:3)을 사용하므로 추가 SQL은 필요 없다. 실제 게임과 멀티 초상화는 공통 목 장식 보정을 사용한다.

명랑이·코기·고양이의 대기·걷기·달리기·점프·공격 대표 프레임과 좌우 방향을 육안 확인했다. 모든 프레임의 착용 품질을 확정한 것이 아니며, 현재 동물별 수치는 사용자 검토 전 초기 보정값이다. 천이 털 뒤에 가려지는 처리는 별도다.

## 재사용 검증 도구

`npm run dev` → `/tools/attachment-fit.html`. 실제 게임 로더와 AnimalAnimationController를 재사용한다. 동작·프레임·방향과 목 부착선을 확인할 수 있다. 동물 선택 후 **폭/두께 슬라이더**를 움직이면 해당 동작의 목 장식 크기를 바로 바꿔 볼 수 있다. 조절은 검증 화면의 메모리 상태만 바꾸며 계정·구매·저장 데이터에는 영향을 주지 않는다. Jua 폰트를 유지하고 새 디자인 리소스는 생성하지 않는다. 도구는 일반 Vite 빌드에 포함되지 않는다.

검증: animal 테스트 114개 통과, 타입 검사·빌드 통과. 회전된 부착선의 양 끝 고정, 폭 변경 시 두께 유지, 두께 변경 시 폭 유지, 실제 Pixi Sprite 변환, 동작별 보정의 독립성, 기존 장착 회귀를 확인했다. 브라우저에서도 폭 2.4/두께 0.4를 슬라이더 입력으로 적용하고 복구했다. 이는 좌표/동작 검증이며 미적 착용 품질의 합격 근거는 아니다.

## 이전 실패 기록

최초 구현은 `neck.width`를 일정 비율로 확대하는 등비 방식이었다. 사용자가 세 펫의 폭·위치가 맞지 않는다고 지적했다. 112개 테스트 통과를 착용 품질의 근거로 삼은 것은 잘못이었다. 이전 `Karakusa_Bandana_Auto_Fit_Comparison.png`는 합격 사례로 재사용하지 않는다. 뒤쪽 띠가 포함된 원본은 목 앞에 얹는 구조가 되어 부자연스러웠다. 현재 구현에서는 앞면 전용 리소스와 독립 두께 계산으로 변경했다.

## 명랑이 목 보정 후속 수정

사용자가 코기·고양이는 괜찮고 명랑이의 목만 맞지 않는다고 확인했다. 공통 변환이나 다른 펫을 다시 바꾸지 않고 명랑이의 collarFit만 조정했다.

- width 2.023 → 1.77 (약 12.5% 축소), height .65 → .55 (약 15.4% 축소)
- x -.418 → -.29, y -.537 → -.68, rotation -.022 → .08: 목 뒤쪽으로 과하게 뻗던 폭을 줄이면서 앞쪽 위치를 유지하고 위로 밀착시킨 초기 보정.
- run의 별도 위치·폭 보정은 유지하고 두께는 새 기본값을 상속한다.
- 명랑이의 대기, 걷기 0/3 프레임, 달리기 0/3 프레임을 육안 비교했다. 전체 프레임의 사용자 검토 완료를 의미하지 않는다.
- 전후 비교: `Resources/Myeongrang_Neck_Fit_Revision.png`. 새 이미지를 생성하지 않고 같은 원본 PNG를 컴포넌트로 렌더링한 결과다.
