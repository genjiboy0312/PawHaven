# 연결 진단과 멀티 방 목록 새로고침

## 2026-11-05

- Supabase 공통 fetch를 기존 12초 제한 그대로 감싸 HTTP 실패·네트워크 오류·시간 초과를 기록한다. 의도적 AbortError 취소와 정상 응답은 기록하지 않는다. 기존 응답/예외를 그대로 돌려준다.
- 현재 실행 세션의 최근 실패 20개만 메모리에 둔다. 새로고침하면 초기화되며 별도 서버 전송·영구 저장은 없다. Realtime/WebSocket 상태와 HTTP 200 응답의 업무상 거절은 이 기록에 포함하지 않는다.
- 기록 필드는 시각·고정 작업 이름·경과 밀리초·HTTP 상태·제한된 오류 코드다. URL/query·요청/응답 본문·헤더·이메일·토큰·채팅·닉네임·원문 오류 메시지는 기록하지 않는다. RPC 동작은 허용된 이름만 포함하고 그 외 경로는 other로 묶는다.
- HTTP 오류 응답 복제본의 최대 2KB에서 PostgREST/SQLSTATE 코드만 추출한다. 실제 SDK 응답은 소비하지 않으며 코드 해석 실패가 통신 결과를 바꾸지 않는다.
- 설정 → 정보에 진단 정보 복사 버튼을 둔다. 현재 빌드와 기록 시각을 함께 복사한다. 클립보드가 차단되면 읽기 전용 입력칸으로 직접 복사하며 페이지 종료 후 늦은 응답은 UI에 반영하지 않는다.
- 멀티 방 목록의 방 만들기 왼쪽에 새로고침을 배치한다. 기존 RoomClient의 list 명령·직렬화·복구 흐름을 재사용하며 조회 중 연속 입력을 막는다. 대기방에는 목록 새로고침 버튼을 표시하지 않는다.
- 진단·씬·멀티 회귀 검사 203개와 타입 검사·빌드 통과. Chrome에서 복사 성공/차단 대안, 새로고침 결과, 한영 960×540/640×360/812×375 배치를 확인했다. 기존 계정 회귀 검사 18개는 앞선 218개 실행에 포함해 통과했다.
- 추가 SQL은 없다. 이번 기능은 원인 수집을 위한 것이며 보고된 간헐적 운영 연결 실패의 원인은 아직 확정하지 않았다. 재발하면 새로고침 전에 진단 정보를 복사한다.
