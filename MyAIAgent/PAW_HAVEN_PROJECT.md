# 1. 프로젝트 개요

## 1.1 프로젝트 비전

Paw Haven은 사용자가 언제든 돌아와 편안하게 쉴 수 있는 작은 동물들의 공간이다.

사용자가 게임을 실행하면 동물들이 사용자의 방문을 알아차리고 반갑게 맞이한다.

웰시코기는 꼬리를 흔들며 달려오고, 고양이는 느긋하게 다가와 인사한다.

사용자는 동물들을 쓰다듬거나 평화롭게 생활하는 모습을 관찰할 수 있다.

장기적으로 다양한 동물, 개인 반려동물 캐릭터, 싱글플레이 놀이터, 멀티플레이를 추가할 수 있도록 설계한다.

## 1.2 핵심 콘셉트

**Welcome Home — 돌아오면 언제나 반겨주는 작은 친구들.**

게임은 경쟁이나 성과를 강요하기보다 동물과의 교감에서 오는 편안함을 우선한다.

### 참고 감성

- 펭귄의 섬
- 포레스트 아일랜드
- 따뜻한 자연 환경
- 평화로운 동물들의 일상
- 귀여운 동물 애니메이션

참고 게임의 분위기만 참고하며 아트, 캐릭터, UI 및 콘텐츠를 그대로 복제하지 않는다.

## 1.3 개발 원칙

1. 동물의 귀여움과 생동감을 최우선으로 한다.
2. 플레이어에게 접속 의무나 죄책감을 주지 않는다.
3. 작은 범위를 높은 완성도로 구현한다.
4. 캐릭터가 추가되어도 기존 코드를 재작성하지 않는다.
5. 웹에서 먼저 검증하고 모바일 앱으로 확장한다.
6. 프로토타입 단계에서는 서버 의존성을 최소화한다.
7. 승인되지 않은 기능을 임의로 추가하지 않는다.

# 4. 기술 스택

## 4.1 권장 기술

| 영역 | 기술 |
|---|---|
| Language | TypeScript |
| 2D Rendering Engine | PixiJS 8 |
| Build Tool | Vite |
| Rendering | PixiJS WebGL 우선 / WebGPU는 추후 검증; Canvas fallback은 현재 구성하지 않음 |
| Animation | PixiJS AnimatedSprite 기반 프레임 애니메이션 |
| Behavior AI | Finite State Machine |
| Persistence | LocalStorage |
| Input | PixiJS 이벤트 시스템 (Mouse / Touch) |
| Audio | @pixi/sound |
| Package Manager | npm |

## 4.2 기술 선택 이유

### PixiJS

- 사용자가 웹게임 렌더링 엔진으로 선택 (2026-10-16)
- 2D 렌더링에 적합
- 브라우저 실행 지원
- 스프라이트 애니메이션 기능 제공
- 터치 및 마우스 입력 지원
- 향후 모바일 앱 패키징 검토 가능
- PixiJS는 렌더링 엔진이므로 씬 생명주기와 행동 AI는 프로젝트에서 별도로 구성

### TypeScript

- 캐릭터 데이터와 행동 상태의 타입 안정성 확보
- 새로운 동물 추가 시 코드 유지보수에 유리
- AI 코딩 에이전트의 코드 생성과 검증에 적합

### Vite

- 간단한 개발 환경
- 빠른 개발 서버
- 웹 빌드 지원

## 4.3 물리 엔진

Prototype v0.1에서는 복잡한 물리 엔진을 도입하지 않는다.

로비의 동물 이동은 단순한 좌표 이동과 애니메이션으로 구현한다.

추후 플랫포머를 개발할 때 PixiJS와 결합할 물리 라이브러리를 요구사항에 따라 별도로 평가한다.

# 5. Prototype v0.1 기능 명세

## 5.1 필수 기능

### FR-001 — 게임 초기화

사용자 승인 진입 흐름: Boot → Preload → Title (터치 안내) → 터치/클릭 후 Lobby → 환영 연출. 시작 입력 전에는 로비 환영을 실행하지 않는다. 타이틀 코기는 표시하지 않으며 추후 타이틀 이미지를 넣을 예정이다. 로비에는 게임 제목과 Welcome Home 텍스트, 수동 생활 조작 버튼을 표시하지 않는다.

- 브라우저에서 게임 실행
- 로딩 화면 표시
- 로비 씬 진입
- 화면 크기 대응

### FR-002 — 힐링 로비

- 자연을 테마로 한 2D 픽셀 아트 공간
- 배경, 지면, 장식 요소 표시
- 동물들이 움직일 수 있는 영역 제공
- 편안한 분위기의 배경음 지원

### FR-003 — 웰시코기

- 사용자 제공 참고 이미지와 일관된 스타일
- 기본 대기 애니메이션
- 이동 애니메이션
- 환영 애니메이션
- 쓰다듬기 반응

### FR-004 — 검정·흰색 턱시도 고양이

- 검은 귀·등·꼬리, 흰 코·입 주변·가슴·배·발
- 웰시코기와 동일한 아트 스타일
- 기본 대기 애니메이션
- 이동 애니메이션
- 환영 애니메이션
- 쓰다듬기 반응

### FR-005 — 자율 행동 AI

동물은 플레이어의 직접 조작 없이 다음 행동을 수행한다.

- 대기
- 산책
- 휴식
- 수면
- 주변 관찰
- 자율 점프 및 착지
- 이모션

행동 전환은 상태 머신을 사용한다.

### FR-006 — 접속 환영

게임 로비 진입 시 환영 시퀀스를 실행한다.

웰시코기:

1. 플레이어의 방문을 알아차린다.
2. 귀를 움직이거나 고개를 든다.
3. 플레이어 방향으로 다가온다.
4. 꼬리를 흔들며 환영한다.
5. 일상 행동으로 돌아간다.

고양이:

1. 플레이어를 바라본다.
2. 잠시 반응한다.
3. 천천히 다가온다.
4. 꼬리를 세우거나 몸을 비비는 동작을 한다.
5. 일상 행동으로 돌아간다.

웹에서는 실제 플레이어 위치를 알 수 없으므로, 화면 안에 정의된 환영 지점으로 접근하는 방식으로 구현한다.

### FR-007 — 동물 상호작용

- 마우스로 동물 클릭
- 터치로 동물 선택
- 쓰다듬기 애니메이션
- 적절한 사운드 재생
- 상호작용 종료 후 일상 상태 복귀

### FR-008 — 기본 설정

- 배경음 켜기/끄기
- 효과음 켜기/끄기
- 설정 로컬 저장

# 7. 캐릭터 아트 가이드

## 7.1 기준 이미지

사용자가 제공한 웰시코기 픽셀 아트 애니메이션 시트를 프로젝트의 주요 아트 레퍼런스로 사용한다.

권장 저장 경로:

`public/assets/references/corgi-style-reference.png`

실제 원본 파일명은 프로젝트에 맞게 변경할 수 있다.

이 이미지는 아트 방향을 정의하는 참고 자료이며, 실제 게임용으로 최적화된 완성형 스프라이트 시트라고 가정하지 않는다.

## 7.2 스타일 특징

- 큰 머리
- 통통한 몸통
- 짧은 다리
- 귀여운 표정
- 부드럽고 풍부한 픽셀 명암
- 따뜻한 자연색
- 지나치게 단순한 8비트 표현 지양
- 동물의 종별 특징 유지
- 프레임 간 체형 및 얼굴 일관성 유지

## 7.3 초기 캐릭터

### Corgi

**ID:** `corgi`

외형:

- 주황색과 흰색 털
- 짧은 다리
- 통통한 체형
- 큰 귀
- 활발한 성격

### Cat

**ID:** `cat`

외형:

- 검정과 흰색 털
- 턱시도 무늬 (흰 코·입 주변·가슴·배·발)
- 통통하고 귀여운 체형
- 긴 꼬리
- 상대적으로 느긋한 성격

## 7.4 애니메이션 규격

전체 동물의 기본 아트 시트는 Idle, Walk, Run, Jump, Fall, Land, Double Jump, Attack, Hit, Die, Skill, Emote, Direction, Climb, Push, Hurt Loop 16종을 기준으로 준비한다. 행동별 게임 연결은 마일스톤 범위에 따라 진행하며, 시트 존재만으로 기능 완료를 표시하지 않는다.

Prototype v0.1에서 우선 필요한 애니메이션:

| Animation | Purpose |
|---|---|
| idle | 기본 대기 |
| walk | 산책 |
| notice | 플레이어 발견 |
| greet | 환영 |
| happy | 쓰다듬기 반응 |
| sleep | 수면 |
| wake | 기상 |

필요한 애니메이션이 실제 원본에 없으면 임시 표현을 사용할 수 있다.

단, 임시 표현을 완성된 최종 아트로 보고하지 않는다.

## 7.5 스프라이트 제작 규칙

- 투명 배경 사용
- 동일 캐릭터의 기준 크기 통일
- 발이 지면에 닿는 위치 정렬
- 애니메이션 프레임별 외형 유지
- 캐릭터 방향 전환 시 가능한 경우 좌우 반전 사용
- 원본 이미지의 품질을 불필요하게 축소하지 않음

스프라이트 프레임 크기는 실제 원본 분석과 게임 테스트 후 확정한다.

## 7.6 새로운 동물 추가 원칙

새로운 동물은 다음 요소만 추가하여 등록할 수 있어야 한다.

- 캐릭터 ID
- 외형 에셋
- 애니메이션 정의
- 이동 속도
- 행동 성향
- 환영 행동 설정

새로운 동물을 추가하기 위해 공통 AI 또는 로비 씬을 복사해서는 안 된다.

# 8. 로비 시스템 설계

## 8.1 로비 역할

로비는 단순한 메뉴 화면이 아니라 동물들이 생활하는 공간이다.

동물들은 플레이어의 직접 입력이 없어도 자연스럽게 움직인다.

## 8.2 로비 구성

초기 공간:

- 작은 정원
- 풀밭
- 나무
- 꽃
- 간단한 쉼터
- 동물 이동 영역

복잡한 공간 꾸미기 기능은 추후 추가한다.

사용자 요청으로 로비에 비동작 메뉴 UI를 배치했다. 좌측 상단 Character, 우측 상단 Friends/Shop/Settings, 우측 하단 Play. 각 원형 이미지 아래 이름을 표시한다. 실제 기능은 후속 구현한다. 상세: [LOBBY_LAYOUT.md](LOBBY_LAYOUT.md).

## 8.3 카메라

사용자 승인 (2026-10-16): 960×540, 16:9 가로 화면을 기준으로 비율 유지 확대/축소한다. 화면이 다르면 여백을 두며 콘텐츠를 자르지 않는다. 모바일 화면 방향은 강제 잠그지 않는다.

Prototype v0.1에서는 고정 카메라를 우선한다.

화면 크기에 따라 적절히 확대 또는 축소한다.

모바일에서 중요한 콘텐츠가 잘리지 않도록 안전 영역을 설정한다.

## 8.4 환영 지점

로비에는 플레이어의 방문을 상징하는 `welcomePoint`를 정의한다.

동물들은 해당 지점을 향해 이동한다.

실제 마우스 포인터나 화면 중앙을 플레이어의 물리적 위치로 취급하지 않는다.

# 9. 동물 AI 설계

## 9.1 상태 머신

```text
AnimalState
├── IDLE
├── WANDER
├── REST
├── SLEEP
├── OBSERVE
├── NOTICE
├── APPROACH
├── GREET
└── PETTING
```

## 9.2 상태 정의

### IDLE

- 일정 시간 대기
- 주변을 관찰
- 다음 행동 선택

### WANDER

- 이동 가능한 영역 안에서 목표 지점 선택
- 걷기 애니메이션 재생
- 목표 도달 시 IDLE 전환

### REST

- 휴식 애니메이션 재생
- 일정 시간 후 다른 행동으로 전환

### SLEEP

- 수면 애니메이션 재생
- 조건 충족 시 기상

### OBSERVE

- 현재 위치에서 주변을 둘러봄
- 일정 시간 후 IDLE 복귀

### NOTICE

- 플레이어 방문 감지
- 고개 돌리기 또는 귀 움직임
- APPROACH 전환

### APPROACH

- 환영 지점으로 이동
- 캐릭터별 이동 속도 적용

### GREET

- 캐릭터별 환영 애니메이션
- 완료 후 IDLE 또는 WANDER 전환

### PETTING

- 사용자의 클릭/터치에 반응
- 행복한 표정 또는 움직임
- 완료 후 이전 일상 행동으로 복귀

## 9.3 행동 우선순위

우선순위:

1. 쓰다듬기 상호작용
2. 초기 환영 시퀀스
3. 일상 행동

중복 애니메이션이나 상태 충돌을 방지해야 한다.

## 9.4 캐릭터별 성향

웰시코기:

- 빠른 이동
- 활발한 환영
- 짧은 대기 시간
- 높은 산책 빈도

고양이:

- 느린 이동
- 차분한 환영
- 긴 휴식 시간
- 높은 수면 빈도

실제 수치는 플레이 테스트를 통해 조정한다.

### WelcomeSequence

- 배경음
- 효과음

# 14. AI 코딩 에이전트 작업 규칙

## 14.1 기본 역할

AI 에이전트는 Paw Haven 프로젝트의 개발 보조자다.

에이전트는 본 문서를 기준으로 승인된 기능만 구현해야 한다.

## 14.2 작업 시작 절차

모든 작업 시작 전에:

1. `MyAIAgent/PAW_HAVEN_PROJECT.md`를 읽는다.
2. 현재 프로젝트 구조를 확인한다.
3. 기존 코드와 구현 상태를 확인한다.

6. 승인된 범위 안에서 구현한다.

## 14.3 구현 원칙

- TypeScript strict 모드를 사용한다.
- 명확한 타입을 사용한다.
- 불필요한 `any`를 피한다.
- 캐릭터 데이터와 행동 로직을 분리한다.
- 중복 코드를 최소화한다.
- 불필요한 라이브러리를 추가하지 않는다.
- 임의로 서버를 만들지 않는다.
- 프로젝트의 아트 방향을 변경하지 않는다.
- 검증하지 않은 기능을 완료로 보고하지 않는다.

## 14.4 금지 사항

명시적인 승인 없이 다음 작업을 수행하지 않는다.

- 멀티플레이 서버 구현
- 로그인 시스템 추가
- 데이터베이스 도입

- 게임 장르 변경
- 기존 캐릭터 디자인 교체
- 과금 시스템 구현
