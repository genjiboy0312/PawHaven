# 코인 수집 일일 퀘스트 (2026-10-28)

- 최종 검증: 전체 320개 테스트·타입 검사·프로덕션 빌드 통과.

- 기존 DAILY_QUESTS에 `coins` 한 항목을 추가한다. 한국어 ‘반짝이는 수집가’, 영어 ‘A pocketful of coins’. 목표 20개, 보상 50코인. 기존 교감/완주 퀘스트의 목표·금액·간식은 유지하며 새 퀘스트에는 간식을 추가하지 않는다.
- 싱글 run_finish와 멀티 race_reward의 최초 승인된 수집량만 합산한다. 완주 보너스 10코인은 수집량에 포함하지 않는다. 중도 포기/DNF/거절된 완주/동일 토큰 재시도/이미 지급한 경기 영수증 재조회는 추가 집계하지 않는다. 진행도는 20에서 제한한다. 이전 지급 기록은 소급 집계하지 않는다.
- 기존 지갑 잠금/영수증 트랜잭션 안에서 daily_coins를 갱신한다. 기존 서버 Asia/Seoul 날짜 초기화에 0으로 초기화하며, 어제 영수증을 오늘 다시 조회해도 오늘 진행도에 추가하지 않는다. 일일 claim ledger에 `daily:날짜:coins`를 기록해 50코인은 하루 한 번만 수령한다.
- 게스트도 기존 ShopState 저장·일일 초기화·beginRun/completeRun을 재사용한다. 기존 저장에 진행도가 없으면 0, 정상 숫자는 최대 20으로 복원한다. 같은 런을 두 번 완료해도 합산하지 않는다. 잔액 상한은 기존 서버와 같은 1,000,000이다.
- 서버 기능 플래그는 dailyCoinQuestReady. 미적용 서버에서는 새 카드와 수령 요청만 생략하고 기존 두 퀘스트는 유지한다. 기존 클라이언트의 daily.claimed 배열은 pet/run만 유지하고, 새 진행도/수령 여부는 daily.coins 및 daily.coinsClaimed로 별도 제공한다. 구형 응답도 파싱한다. 서버 뷰는 새 boolean을 기존 공통 카탈로그의 claimed 상태로 변환해 사용한다.
- QuestPopup의 기존 카드·완료 색상·수령 버튼·탭 알림·스크롤·Jua·PNG 표면을 재사용한다. 새 씬/이미지/패널을 만들지 않는다. 기존 상태 observer를 통해 완주 확정/수령 후 즉시 갱신한다.
- SQL 이름 **Daily Coin Collector Quest**. 파일 `supabase/migrations/202610280025_daily_coin_quest.sql`. Multiplayer Finish Rewards(024) 이후 실행한다. daily_coins 열을 IF NOT EXISTS로 추가하고 기존 저장·재화·보유량·지급 기록을 보존한다. 사용자가 2026-10-28 실행 완료를 확인했다.
- 검증: PostgreSQL(PGlite)에서 싱글 7개 + 멀티 10개 + 싱글 7개 → 20 제한, 중복 요청/다른 UUID 재지급/미완주 제외, 50코인 1회·간식 보존, 서버 날짜 초기화 및 이전 영수증 재조회 미집계, SQL 재실행, 응답 검증, 구형 서버 요청 생략을 확인했다. 게스트 저장 복원·날짜 초기화도 확인했다. 실제 Chrome에서 세 카드/0→20/완료 색상·수령/50코인 증가·간식 불변/수령 상태 저장/640×360·812×375 스크롤과 경계/영어 표기를 확인했다.
