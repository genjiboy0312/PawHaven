# 가구 상점 및 펫 소파 (2026-10-21)

- Shop 탭: Style / Furniture / Pass. Furniture 안에는 Furniture / Etc 상품 목록을 두며 기존 Shop 그리드·구매 영역을 재사용한다. 배경·바닥은 기존 무료 선택을 유지한다.
- 기존 가구 4종·기타 4종은 기본 3개를 유지한다. 새 `Furniture:5`는 검정·화이트 펫 소파이며 초기 0개, 1개당 250코인이다. 기존 아이템은 `100 + 인덱스 × 25`코인. 종류별 최대 보유량 20개다.
- 구매는 1개 단위이며 보유 중이어도 추가 구매할 수 있다. 가격·전체 보유량·한도·코인 부족·처리 중·연결 대기를 표시한다. 코인 차감과 수량 증가는 같은 저장/DB 트랜잭션에서 처리한다.
- Home 아이템창의 남은 수량은 전체 보유량에서 배치한 수를 뺀 값이다. 0개면 흐리게 표시하고 배치를 막는다. 회수는 배치 하나만 제거하며 전체 보유량/코인을 변경하지 않는다. 기존 드래그·개별 ID·좌표 저장을 재사용한다.
- 게스트는 기존 `pawhaven.shop.prototype.v1`에 `homeItems`를 추가 저장한다. 기존 키·코인·의상·패스는 유지한다. 계정은 별도 서버 수량을 사용하며 게스트 수량/잔액을 계정으로 가져오지 않는다.
- 계정의 배치는 기존 클라우드 꾸미기 저장에 남는다. 보유 수량을 아직 불러오지 못해도 배치 원본을 삭제하지 않고, 수량 확인 후 표시 개수를 제한한다. AccountStorage 정규화는 종류별 최대 20개를 보존한다. 보유 수량 변화 시 로비와 홈의 화면을 갱신한다.

## 소파 이미지

- 원본: `Resources/Pet_Sofa_Black_White_Prototype.png`.
- 배포용 복사: `public/assets/home/pet-sofa-black-white.png`. 바이트가 동일하며 PNG 재가공·재생성은 하지 않았다.
- 이미지 크기 1254×1254, alpha>1 범위 `(109,461)–(1147,864)`를 측정했다. Pixi에서는 패딩 2px를 더한 프레임 `(107,459,1042,407)`만 표시한다. 폭 170, 발 기준 anchor `(0.5,0.9)`, nearest 스케일링.
- HTML 아이콘/상점 미리보기에서도 CSS로 동일 영역을 표시한다. 아이템창·상점·홈·로비가 같은 PNG를 참조한다. 캐릭터 크기·모션·플레이 맵은 바꾸지 않는다. 소파에 앉거나 눕는 새 인터랙션은 이번 범위가 아니다.

## Supabase

`supabase/migrations/202610210008_home_shop.sql` 전체를 SQL Editor에서 한 번 실행한다. 001/002가 적용된 프로젝트용이며 재실행 가능하다.

- `economy_home_items` 테이블: 계정/분류/인덱스/전체 수량. RLS는 본인 조회만 허용하며 클라이언트 직접 쓰기는 금지한다.
- 기존 `economy_command`에 `buy_home`을 추가한다. 기존 구매/보상/런 처리 분기는 유지한다. 서버에서 상품·가격·보유 한도·잔액을 검증하고 기존 지갑 행 잠금, 요청 ID 중복 방지, 분당 요청 제한을 공유한다.
- 스냅샷에 `homeShopReady:true`, `homeItems`를 추가한다. 기본 제공량은 카탈로그/서버에서 계산하며 구매 이력이 있는 항목의 전체 수량만 저장한다.
- SQL 미실행 상태의 구형 스냅샷도 읽을 수 있다. 기존 상점은 유지하고 가구 구매만 대기로 표시하며 `buy_home` 요청을 보내지 않는다. 실행 후 새로고침하면 구매할 수 있다.

## 검증

전체 테스트 170개, 타입 검사·빌드 통과. PGlite에서 실제 신규 migration과 기존 경제/RLS 테스트를 실행했다. 추가 검증: 서버 가격 강제/계정 분리/중복 재시도/잔액 부족/수량 한도/요청 제한/비정상 응답, 게스트 저장 및 계정 버킷, 클라우드 배치 보존, Shop 클릭→Home 배치→로비 표시→회수, 원본/배포 PNG 동일성, 공유 텍스처 생존. 실제 브라우저·모바일 화면의 시각 검증은 별도 필요하다.
