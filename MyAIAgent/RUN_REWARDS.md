# 싱글 완주 코인 보상 (2026-10-28)

- 최종 검증: 전체 316개 테스트·타입 검사·프로덕션 빌드 통과.

- 기존 CoinCollection과 완주 토큰을 연결한다. 신규 리소스 없이 결과창에 수집 코인/전체 수, 확정 획득 보상, 현재 잔액을 표시한다. 서버 대기·실패 시 보상을 먼저 더하지 않으며 기존 commerceStatus의 재시도 버튼을 재사용한다. 공통 Jua·CoinAmount·결과 패널을 유지한다.
- 지급액은 완주 10코인 + 수집 개수(각 1코인). 지갑 1,000,000 한도까지 실제 더해진 금액을 표시한다. 기존 XP 100/일일 완주 진행과 일일 퀘스트 수령 100코인은 별개로 유지한다. 멀티플레이는 기존 개인 수집 요약만 유지하며 이번 지급은 싱글에만 적용한다.
- 게스트는 beginRun으로 시작한 런을 completeRun에서 한 번만 지급하고 기존 상점 저장에 잔액을 저장한다. 계정은 기존 EconomyClient/EconomyRequest 큐와 지갑 잠금을 재사용한다. Game은 시작 시 map, 완주 시 collected만 전달하며 지급액은 보내지 않는다.
- SQL은 토큰에 course_id를 기록한다. 맵별 수집 상한은 Practice 7/Garden 10/Forest 11/Crossroads 13. 정수·본인 토큰·미사용·서버 시작 후 4초 이상·15분 이내를 검사한다. 소비 표시/코인/XP/퀘스트/영수증을 같은 트랜잭션에 저장한다. 클라이언트가 보낸 가격/보상액은 사용하지 않는다. coins_collected/reward_coins로 지급 기록을 남긴다.
- 수집 개수는 클라이언트 보고 값에 서버 상한을 적용한 것이다. 실제 이동 경로나 각 코인과의 충돌을 서버에서 재생 검증하는 기능은 포함하지 않는다. 완전한 부정행위 방지나 서버 시뮬레이션으로 설명하지 않는다.
- 응답 유실은 같은 요청 UUID로 재시도한다. 동일 토큰에 새 UUID로 다시 요청하면 추가 지급하지 않는다. run_id와 run_reward 영수증을 함께 반환하며 ServerShopState가 현재 결과의 토큰과 일치할 때만 확정한다. 결과창은 동일 observer를 구독하므로 재시도 성공 시 열린 상태에서도 확정 금액/잔액을 갱신한다. 씬 종료 시 구독을 해제한다.
- SQL 이름 **Single Run Coin Rewards**. 파일: `supabase/migrations/202610280023_single_run_rewards.sql`. Lobby Background Shop(022) 뒤 실행한다. runRewardsReady 기능 플래그가 없으면 기존 XP/퀘스트 완주만 처리하고 새 코인 보상은 준비 중으로 표시한다.
- 실서버에서 `column w.snacks does not exist` 오류를 사용자에게 확인했다. SQL 앞부분에서 누락된 snacks/last_snack 열만 IF NOT EXISTS로 추가하도록 보완했다. 기존 잔액/간식 수량/쿨다운은 덮어쓰지 않는다. 간식 열 누락 상태를 로컬 DB에서 재현해 복구·잔액/보유량 보존·완주 지급을 확인했다. 사용자가 2026-10-28 보완 SQL 실행 성공을 확인했다.
- 검증: 실제 PostgreSQL(PGlite)에서 맵별 금액/상한, 중복 재시도, 다른 계정 토큰, 너무 빠른 완주/만료, 잘못된 수집 값, 직접 쓰기 거부, 지갑 한도, SQL 재실행과 간식 필드 누락 복구를 확인한다. 실제 서버 어댑터의 응답 유실 후 재시도는 한 번만 지급하며 구독 상태를 갱신한다. 게스트 저장·중복 지급 방지도 확인한다. Chrome 실제 PlayScene에서 지급 요약, 서버 대기 중 잔액 보존, 포인터 재시도→확정, 640×360·812×375 결과 경계, 복귀 후 잔액을 확인했다. 브라우저 서버 통신은 테스트 전송기를 쓰며 실제 DB 검증과 구분한다.
