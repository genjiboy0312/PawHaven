# 멀티 방 초대 링크 (2026-10-22)

## 사용자 흐름
- 대기방의 Invite / 초대 버튼은 방장·방원 모두 사용할 수 있다. 진행 중·결과 화면에는 표시하지 않는다.
- 터치 기기에서 Web Share API를 지원하면 클릭 이벤트 안에서 공유창을 연다. 사용자가 취소하면 복사하지 않는다.
- 데스크톱 또는 공유 불가 환경은 Clipboard API로 복사한다. 복사도 거부되면 읽기 전용 링크를 선택해 직접 복사할 수 있다.
- 링크는 현재 앱 경로에 `?room=<UUID>`만 붙인다. OAuth code/token/hash 및 기존 쿼리는 공유하지 않는다.
- 링크 접속 후 타이틀을 터치하면 기존 멀티 패널에서 초대 방을 표시한다. 로그인 전에는 로그인 안내, 로그인 후에는 방 이름·맵·인원수·Join을 보여준다. 링크만으로 입장·Ready하지 않는다.
- 닫힌 방, 만원, 진행 중인 방은 기존 안내로 표시한다. 기존 방 참가 중에는 먼저 나가도록 안내하며 강제로 다른 방에 입장하지 않는다.
- 초대 닫기 또는 해당 방의 참가가 확인되면 보류 초대와 URL의 room만 지운다. 입장 실패나 로그인 화면 이동만으로는 초대를 소진하지 않는다.

## 재사용과 수명
- RoomInvitation은 URL의 단일 UUID를 검증하고 탭별 sessionStorage에 30분간 복원 가능한 초대를 저장한다. 명시적 잘못된 room 값은 과거 초대를 이어받지 않는다.
- Google OAuth의 기존 깨끗한 callback URL과 Supabase 허용 주소는 변경하지 않는다. Game이 OAuth SDK 초기화 전에 초대를 저장하고, 로그인 후 같은 탭의 보류 초대를 복원한다. 이메일 로그인도 같은 메모리 초대를 유지한다.
- sessionStorage가 차단되면 현재 페이지의 초대는 동작하지만 OAuth 전체 이동을 넘어서는 보존은 보장하지 않는다. 이 경우 로그인 후 원래 초대 링크를 다시 연다. 다른 브라우저·새 탭으로 OAuth가 반환하는 환경도 별도 확인 대상이다.
- PlayMenuPopup은 기존 RoomClient 옵저버로 미리보기를 갱신하고, Join 시 기존 인증 join RPC를 호출한다. 정원·진행 상태·중복 참가·권한 검증은 서버에서 유지한다.
- RoomClient.listed는 첫 서버 응답 전의 빈 목록을 닫힌 방으로 오인하지 않도록 구분한다. 현재 목록 RPC의 최대 80개 노출 범위 안에서 미리보기를 제공한다.
- RoomInviteButton이 공유/복사 UI를 담당한다. 중복 탭을 막고 메뉴 재렌더·닫기 시 리스너를 해제하며 늦은 비동기 응답이 제거된 UI를 갱신하지 않게 한다.
- 기존 크림 패널·commerce-primary 버튼·폰트·영어/한국어를 재사용한다. 새로운 이미지·라이브러리·SQL·상시 네트워크 호출은 없다.

## 검증
- 경로 보존, 민감 쿼리/hash 제거, UUID·중복 room 거부, 탭 보존·만료·명시적 취소.
- native 공유 성공·취소, 공유 실패 후 복사, 복사 거부 후 직접 선택, 중복 클릭·제거 후 응답.
- 실제 로컬 PostgreSQL로 초대 미리보기→명시적 Join, 만원·시작·폐쇄 방, 기존 방 우선 처리를 검증한다.
- Google OAuth mock으로 기존 callback URL을 유지하면서 sessionStorage에서 초대를 복원하는지 검증한다.
- 실제 모바일 공유창, 운영 Google 로그인 왕복과 두 기기 입장은 실기기 확인이 필요하다. 공유 API의 성공은 상대방이 링크를 받거나 입장했다는 보장이 아니다.

참고: OAuth 복귀 주소는 기존 [Supabase Redirect URLs 규칙](https://supabase.com/docs/guides/auth/redirect-urls)을 유지한다.
