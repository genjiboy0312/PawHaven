# 하루 한 번 출석 우편 (2026-10-29)

- 로그인한 계정이 로비에 들어오면 30코인 출석 우편을 확인한다. 게스트에게는 지급하지 않는다. 달력·새 버튼·자동 수령 팝업 없이 기존 우편함과 로비 미수령 표시를 재사용한다.
- SQL `202610290029_daily_attendance_mail.sql`, SQL Editor 이름 **Daily Visit Reward Mail**. 사용자가 2026-10-29 실행 완료 확인. 기존 Garden Props Shop(021) 이후 적용하며 최신 경제/구매/퀘스트 함수는 덮어쓰지 않는다.
- `daily_attendance_mail()`은 인자 없이 auth.uid와 서버 clock_timestamp의 Asia/Seoul 날짜를 사용한다. 사용자·날짜·금액·키를 클라이언트에서 지정할 수 없다. 기존 player_mail의 `(user_id, delivery_key)` 유니크 키 `attendance:YYYY-MM-DD`를 재사용해 계정/날짜당 한 통만 만든다. 기존 경제 초기화/지갑 잠금→우편 순서를 유지한다.
- 우편은 30일 보관한다. 보낼 때 잔액을 올리지 않고 기존 mailbox_command 받기/모두 받기에서 30코인을 지급한다. 코인 상한에 걸리면 우편을 미수령 상태로 유지한다. 수령 응답 유실 재시도도 기존 claimed_at/잠금으로 중복 지급하지 않는다.
- 기존 우편함 함수의 가구 초기 재고·수령 영수증을 보존한다. mail.kind의 attendance/system 메타데이터만 추가하며 구형 클라이언트도 추가 필드를 허용한다. 출석 제목·본문은 현재 게임 언어의 Jua 문구를 사용하고, 일반 관리자 우편의 제목/본문은 그대로 유지한다.
- MailboxClient.start는 로비 진입마다 출석을 확인한다. 진행 중인 우편 요청이 있으면 뒤에 처리하고, 불확실한 요청은 기존 pendingRequest로 재시도한다. 기존 30초 폴링은 load를 유지한다. 자정이 지나도 같은 화면에 계속 머물면 다음 로비 진입 시 새 날짜를 확인한다.
- 전용 RPC가 없는 서버(PGRST202/42883)는 기존 load로 대체하여 우편 수령을 막지 않는다. 인증/통신 오류를 성공으로 바꾸지 않으며, 계정 변경·씬 수명 처리는 기존 클라이언트 소유권/AbortSignal 규칙을 따른다.
- 검증: 전체 338개 테스트·빌드 통과. DB 날짜/KST/계정 분리/수령 전 잔액/일별 한 통/재실행/코인 상한/권한/과거 날짜 분리/응답 유실 재시도, 구형 RPC 호환/진행 중 요청 뒤 출석 확인을 검증했다. 실제 Chrome 우편함+모의 transport에서 한·영 표시와 받기 1000→1030/미수령1→0/30코인 영수증을 확인했다. 실서버 계정에서의 운영 확인과 구분한다.
