# Single Records and Goals Sync

## 범위와 원칙
- 싱글 맵별 최고 기록과 달성 목표를 계정에 저장한다. 기존 맵 선택/결과 화면과 공통 폰트를 재사용한다.
- `SingleRecords`는 기록 모델과 변경 구독을, `SingleRecordSync`는 비동기 계정 동기화를 담당한다. 꾸미기 JSON의 revision/충돌 처리와 섞지 않는다.
- 개인 기록은 클라이언트가 보고하는 비공개 진행 정보다. 경쟁 순위, 코인, 경험치, 퀘스트 보상 판정에는 사용하지 않는다. 보상은 기존 서버 검증을 유지한다.

## 병합과 저장
- 같은 계정의 다른 기기는 레이스 최소 시간, 서바이벌 최대 생존 시간과 이미 달성한 목표를 합친다. 오래된 응답으로 기록을 되돌리지 않는다.
- `AccountStorage.singleRecords(owner)`는 생성 시 소유 계정을 고정한다. 계정 변경 후 이전 객체가 다른 계정 키에 쓰지 않으며 꾸미기 dirty 상태도 바꾸지 않는다.
- 기존 로컬 v1/v2 기록을 읽는다. 게스트 기록은 자동 합치지 않고 설정 → 계정 → 싱글 기록 → 게스트 기록 가져오기 확인 후 병합한다. 가져오기 취소는 아무것도 바꾸지 않는다. 기존 게스트 데이터는 유지한다.
- 초기 다운로드와 새 완주 기록 업로드를 직렬화한다. 요청 중 새 기록이 생기면 다음 요청으로 최신 상태를 보낸다.
- 연결 실패 시 기기 기록을 보관한다. 계정 설정의 기록 동기화 버튼과 기존 네트워크 복귀 복구 흐름으로 재시도한다. 서버 SQL 미적용/권한 오류는 별도 안내하며 무한 재시도하지 않는다.
- 계정 전환/게임 종료 시 구독 해제 및 요청 취소. 늦은 응답은 적용하지 않는다.
- 맵 선택을 열어 둔 상태에서 기록이 도착하면 텍스트와 목표만 갱신해 포커스·선택·스크롤을 유지한다.

## SQL 적용
- SQL Editor 쿼리 이름: **Single Records and Goals Sync**
- 파일: `supabase/migrations/202611070037_single_record_sync.sql`
- `player_single_records`는 본인 행만 SELECT 가능하다. 직접 쓰기 및 익명 RPC 실행은 차단하며 인증 RPC로만 병합한다.
- RPC `sync_single_records`는 사용자 ID를 세션에서 얻고 허용 맵·시간 범위·목표 형식을 검사한다. 최소 시간과 무낙하 달성을 병합하며 시간 목표는 맵별 기준으로 계산한다.
- 기존 재화·꾸미기 테이블을 변경하지 않는다. 파일은 다시 실행할 수 있다. 운영 반영은 사용자 SQL Editor 실행이 필요하다.

## 검증
- 관련 기존 테스트 151개 통과 후 추가 DB/전송 검증 2개 통과. 새 테스트는 `tests/single-record-sync.test.mjs`, 네트워크 복귀 검증은 `tests/network-recovery.test.mjs`.
- 실제 로컬 PostgreSQL(PGlite): 계정별 접근 분리, 직접 쓰기/익명 접근 차단, 두 기기 복원, 최소 기록·목표 병합, 잘못된 입력의 원자적 거부, 재실행.
- 비동기 요청 중 기록 변경, 오프라인 보존/재시도, SQL 미적용 복구, 계정 변경/종료 후 응답 무시, 명시적 게스트 가져오기, 현재 세션 토큰 사용 검증.
- Chrome에서 실제 UI 컴포넌트로 기록 도착 후 포커스 유지, 가져오기 취소/확인, 공통 Jua 폰트, 모바일 가로 폭을 검증했다.
- 타입 검사와 프로덕션 빌드 통과. 운영 Supabase 로그인 계정의 실제 두 기기 검증은 SQL 반영 후 별도 확인한다.


## 2026-11-07: 싱글 서바이벌 기록 확장
- `survival`, `terraces` 각각 최고 생존 시간을 밀리초로 저장한다. 레이스의 `complete`와 별도로 `survive(map, seconds, cleared)`를 사용한다.
- 최대 30초. `finish`는 실제 `SurvivalRound.succeeded`일 때만 기록한다. 30초 경계에 탈락한 시간만으로 클리어를 추정하지 않는다. 서버 병합은 최대 시간과 클리어 OR를 각각 유지한다.
- v2 페이로드와 기존 테이블/RPC를 확장한다. 레이스 최소 시간·목표 병합, 계정 분리·명시적 게스트 가져오기를 그대로 재사용한다.
- SQL Editor 이름: **Survival Personal Records**. 파일: `supabase/migrations/202611070040_survival_records.sql`. 037 이후 적용. `survival_cleared` 열과 맵/범위 제약 추가. 재실행 가능하며 기존 기록은 유지한다.
- 구버전 SQL의 `22023`은 설정 필요 상태로 표시한다. 로컬 기록은 보존하고 자동 반복 요청을 중지하며, 적용 후 계정 패널의 동기화 버튼으로 복구한다.
- 맵 카드와 결과창은 공통 `singleBestLabel`/`singleGoals`를 사용한다. 최고 시간 / 30s, 클리어 배지, 새 최고 기록을 표시한다. 새 이미지나 경제 보상은 추가하지 않는다.
- 검증: 전체 449개 회귀 테스트 통과. 로컬 PostgreSQL(PGlite)에서 최대/최소 시간 분리, 클리어 독립 보존, 권한·잘못된 입력 원자적 거부·재실행·두 기기 복원 검증. 실제 운영 계정 간 복원은 SQL 적용 후 별도 확인한다.
- 실제 Game을 Chrome 844×390 가로 viewport에서 실행해 탈락 기록, 새로고침 후 보존, 30초 클리어 배지와 패널 범위를 확인했다. 테스트에서는 시간/좌표를 제어했으며 자연 플레이 난이도나 실제 휴대폰·운영 계정 검증을 뜻하지 않는다.
