# Cozy UI 1차 (2026-10-17)

## 디자인
- 사용자가 제공한 Party Animals UI의 둥근 형태·넉넉한 여백·부드러운 입체감을 참고했다. 게임 원본 로고/이미지를 복사하지 않고 CSS로 구성한다.
- 로딩/타이틀 글자와 Settings·Quest·Friends 팝업을 먼저 적용했다. Character/Home/Shop의 인벤토리 구조와 아이템 아래 타원 그림자는 유지한다. 공용 DOM 글꼴은 새 폰트를 사용한다.
- 크림색 패널, 버터색 제목줄, 살구색 선택 탭, 연두색 보상/주요 버튼. 얇은 테두리·안쪽 하이라이트·낮은 그림자로 도톰한 버튼을 표현한다.
- 제목과 버튼: Jua. 설명/긴 문장: Gowun Dodum. 타이틀은 대문자 둥근 글자에 크림색·얕은 돌출 그림자를 적용한다.
- 팝업은 기존 닫기/포커스/일시정지/한영 전환·보상 준비/수령·비활성 상태를 유지한다. 탭은 가로 스크롤, 본문은 세로 스크롤이 가능하다.
- reduced-motion 설정에서는 버튼 전환과 기존 타이틀 안내 애니메이션을 줄인다. 픽셀 동물의 몸체 크기/동작/히트 영역과 플레이 조작은 변경하지 않는다.

## 폰트와 배포
- 공식 배포본: https://github.com/google/fonts/tree/main/ofl/jua 및 https://github.com/google/fonts/tree/main/ofl/gowundodum.
- 원본 TTF의 글리프를 삭제하지 않고 fontTools + Brotli로 WOFF2 형식만 변환했다.
- public/assets/fonts/Jua-Regular.woff2 368,836 bytes, GowunDodum-Regular.woff2 445,388 bytes. 대응 OFL 원문을 함께 배포한다. 다운로드/로컬 변환은 제작 단계 작업이며 npm/CI 추가 의존성은 없다.
- index.html에서 선로딩한다. CSS @font-face의 font-display:swap으로 지연/실패 시 대체 글꼴도 표시한다. 외부 폰트 서비스에 런타임 요청하지 않는다.
- Boot/Preload 문구를 DOM으로 표시해 웹폰트가 늦게 로드돼도 바뀌게 했다. 씬 종료 시 캡션을 제거하고, 기존 중복 로딩 문구 방지도 유지한다. 진행 막대는 Pixi Graphics를 사용한다.
- 스타일은 src/ui/cozy-theme.css에 모았으며 src/main.ts에서 기존 style.css 다음에 불러온다.

## 검증
- 테스트 69개·타입 검사·빌드. 새 Boot/Preload 문구의 1개 유지와 씬 종료 정리, 기존 타이틀 시작/팝업/번역/보상/터치/저장 회귀를 확인했다.
- 변환 폰트의 woff2 재열기와 주요 한영 글리프 존재를 확인했다. 로컬 HTTP 응답 200, 빌드 결과의 상대 폰트/선로딩 경로도 확인했다.
- 브라우저 도구가 Windows sandbox helper 오류로 시작하지 못했다. 최종 시각·작은 모바일에서의 글자/탭 여백은 실기기 확인이 필요하다.

## 2026-10-19 로비 버튼
- 사용자 승인으로 로비 7개 메뉴의 그림과 표면 스타일만 변경했다. Character/Home 좌측, Quest/Friends/Shop/Settings 우측 상단, Play 우측 하단의 기존 배치를 따른다.
- 기존 인라인 SVG 아이콘을 직접 수정해 파스텔색 면·둥근 외곽선으로 통일했다. 아이콘 아래 한영 이름과 접근성 라벨을 유지한다. 새 이미지 생성·다운로드나 라이브러리 추가는 없다.
- 크림색 원형 바탕에 얇은 베이지 테두리, 안쪽 하이라이트와 낮은 그림자. Play는 더 큰 연두색 원형과 흰 재생 아이콘, 아래 크림색 이름으로 강조한다.
- 누르면 아이콘과 이름이 작게 내려가고 그림자가 줄어든다. 마우스 hover는 fine pointer에서만 적용하고 reduced-motion에서는 이동 효과를 끈다.
- 키보드 포커스를 원형 아이콘 테두리에 표시한다. 비활성은 채도/투명도를 낮추고 버튼 터치 영역은 최소 44px로 둔다. Quest 보상 알림과 공통 클릭음/씬 이동은 기존 흐름을 사용한다.
- Windows 브라우저 확인 도구가 커널 초기화 실패로 실행되지 않았다. 실제 모바일의 아이콘/라벨 크기와 화면상 간격은 사용자 확인이 필요하다.
- 검증: 기존 자동 테스트 114개·타입 검사·프로덕션 빌드 통과. 시각 변경 전용 테스트는 추가하지 않았다.

## 2026-10-19 Character 화면 적용
- 로비에서 확정한 크림·버터·연두색 표면과 낮은 그림자를 Character 탭·닫기·프리셋에 적용했다.
- 아이템 그림자/4열 목록/선택 즉시 착용은 유지한다. 프리셋 상태는 저장 대상과 현재 모습의 일치 여부를 구분한다.
- 스타일 선택자는 Character 화면 내부로 한정했다. 상세: [CHARACTER_SCENE.md](CHARACTER_SCENE.md).

## 2026-10-19 Shop 화면 적용
- Shop 범위 안에서 Style/Pass·아이템 분류 탭을 크림색·버터색으로 통일하고, Close를 × 원형 버튼으로 정리했다. Character/Home 및 Quest의 공용 패스 UI에는 스타일을 전파하지 않는다.
- 아이템 아래의 옅은 그림자를 유지하고 선택 상품만 얇은 테두리로 구분한다. 보유 상품 가격 위치에는 체크+보유 중을 표시한다.
- 구매 영역을 하나의 바닥 영역으로 묶고 상품명·가격·구매 버튼을 함께 배치한다. Hat:1은 실제 상품명 산타모자/Santa Hat, 다른 프로토타입 상품은 기존 분류+번호를 사용한다.
- 버튼은 구매 가능(연두)/보유·구매 완료(옅은 녹색)/코인 부족(살구)/처리·조회 중(버터)/연결 확인 필요(회색)를 구분한다. 상태는 문구로도 표시하며 기존 비활성·서버 검증 규칙을 유지한다.
- 서버 재화 첫 조회 전에는 Coins: —로 표시하며, 로컬 기본값을 계정 잔액으로 보여주거나 기본 아이템을 보유한 것처럼 표시하지 않는다.
- 구매 요청과 서버 응답 중 목록의 스크롤 위치를 보존한다. 현재 선택 상품과 다른 상품의 응답이 도착해도 구매 완료 표시는 실제 구매한 분류/번호에만 붙인다.
- 한영 변경 시 화면을 다시 표시하고 언어 리스너를 씬 종료 시 해제한다. 기존 캐릭터 미리보기/구매 후 이모션/패스 테스트 해금 규칙은 유지한다.
- Shop 테스트에서 최초 조회·임시 잔액 숨김·보유/구매 가능/처리 중/구매 완료·스크롤 유지·중복 차감 방지를 검증한다. 실제 모바일 화면 배치와 터치 느낌은 별도 확인 대상이다.
- 최종 검증: 전체 114개 자동 테스트·타입 검사·프로덕션 빌드 통과. 새 SQL 적용은 필요하지 않다.
