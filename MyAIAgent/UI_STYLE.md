# Cozy UI 1차 (2026-10-17)

## 싱글 나가기 통일 (2026-10-23)
- 싱글 패널도 멀티 목록과 같은 footer 좌측 나가기를 사용한다. 상단 ←는 숨기고 포커스 대상에서 제외한다. 나가기는 모드 선택으로 돌아간다. 맵 변경 팝업과 Play 배치는 유지한다.

## 멀티 나가기 위치·외형 저장 순서 (2026-10-23, 이전 화살표 규칙보다 우선)
- 멀티 방 목록과 대기방에서 상단 ←는 숨기고 disabled로 포커스 대상에서도 제외한다. 나가기는 footer 좌측으로 통일한다. 목록에서는 모드 선택으로 돌아가고, 대기방에서는 기존 확인창 후 leave한다. 방 생성·싱글의 ←와 모드 선택의 ×는 유지한다. 확인창 취소 시 하단 나가기 버튼으로 포커스를 복구한다.
- roomTransport가 저장 완료를 기다리지 않고 create/join을 보냈고, Game도 저장 중이면 canSave=false라 저장 대기를 생략하던 경쟁 조건을 수정했다. pendingSave이면 AccountService.save의 진행 중 저장/추가 변경 처리까지 기다린다.
- prepareRoomAppearance를 일반 생성·입장과 친구 초대 수락에서 재사용한다. 저장 실패 또는 4초 대기 초과 시 마지막 서버 확정 외형으로 입장을 계속하고, 요청 취소 시 대기를 끝낸 뒤 인증·취소 신호를 재검사한다. 저장 성공 경로에서는 최신 외형으로 입장한다. 서버 테이블이나 SQL 변경은 없다.
- 전체 221개 테스트·타입 검사·빌드 통과. 실제 PGlite 방 참가자 snapshot의 명랑이/모자 반영, 일반 입장·초대 수락의 저장 선행, 저장 오류·시간 제한·취소·계정 재확인과 하단 나가기를 검증했다.

## 모드 선택·닫기 테두리 통일 (2026-10-23)
- Choose Mode 본문에 3cqh 상단 여백을 두고 모드 버튼 행 높이를 clamp(64px,18cqh,120px)로 제한한다. 다른 맵 선택 카드에는 적용하지 않는다.
- 캐릭터·상점 ×의 크기와 위치는 유지하고 설정 패널 닫기 버튼과 같은 테두리 색·그라데이션·그림자를 적용한다. 작은 버튼에 비례하는 35% 모서리 반경으로 둥근 사각형을 통일한다.
- 타입 검사·빌드 통과. Chrome headless 800×540 및 520×400에서 모드 버튼의 상단바 비침범·패널 내부 배치·비중첩, 캐릭터/상점 닫기 버튼의 둥근 사각형·경계 포함을 확인했다.

## 대기방 하단 액션·캐릭터 닫기 (2026-10-23)
- 대기방 footer는 본문 스크롤과 분리한다. 좌측 Leave, 우측 Share link → Invite friend(방장만) → Start/Ready 순서다. 시작·준비는 연두색으로 강조한다. 링크 복사 실패 시 선택 가능한 URL과 안내는 footer 내부 다음 줄에 표시하며, footer 높이는 28cqh로 제한하고 필요하면 내부 스크롤한다.
- 캐릭터 씬 우상단 ×는 top 7cqh/right 4.5cqw, 크기 clamp(28px,3cqw,38px), 글자 clamp(20px,2.2cqw,28px)로 축소해 인벤토리 패널 안에 둔다. 기존 44px 최소 크기는 제거하고 탭과 겹치지 않게 한다. 다른 씬의 닫기 버튼 규칙은 유지한다.
- 전체 217개 테스트·타입 검사·빌드 통과. Chrome headless 800×540 영어 대기방/캐릭터와 520×400 한글 대기방에서 경계·버튼 순서·탭 비중첩을 확인했다. 일반 참여자의 초대 버튼 숨김과 링크 복사 대체 UI도 확인했다. 임시 화면 데이터는 운영 코드에 포함하지 않는다.

## 사용자 승인 기준 (2026-10-23, 이전 시안 기록보다 우선)
- 사용자가 현재 배포된 조이스틱·Attack·Dash·Jump UI를 확인하고 승인했다. 기준 구현은 커밋 df4fdb5이며, 변경 요청 없이 저해상도 도트 방식으로 되돌리거나 새 디자인을 다시 생성하지 않는다.
- 픽셀 밀도 참고: Resources/Pet_Sofa_Black_White_Prototype.png. 큰 픽셀 알갱이가 드러나는 확대 대신 촘촘하고 자연스러운 윤곽과 절제된 색 단계를 사용한다.
- 승인 수치: 아이콘 64격자, 버튼 바탕·손잡이 96격자, 조이스틱 바닥 128격자. 정수 격자 SVG 윤곽은 유지하고 강제 pixelated 확대는 적용하지 않는다.
- 글자는 기존 Jua 둥근 폰트와 한영 번역을 사용한다. 영어 5×7 도트 글자 확대는 사용하지 않는다. 버튼 크기·발바닥 배치·색상·좁은 아이콘/글자 간격·입력 및 쿨다운 동작을 유지한다.
- 기존 컴포넌트와 scripts/generate-touch-controls.mjs를 재사용하고, 리소스는 Resources/Control_*와 public/assets/controls에 함께 저장한다. 이미지 변경 시 캐시 갱신용 버전도 조정한다. 상세: [TOUCH_UI_APPLIED.md](TOUCH_UI_APPLIED.md).

## 멀티 Create room 크기 보정 (2026-10-23)
- 방 목록과 방 생성 화면의 Create room 버튼은 너비 clamp(104px,12cqw,172px), 높이 clamp(32px,5cqh,44px), 글자 10~17px로 제한한다. 이전 18cqw×7cqh 크기를 재사용하지 않는다.
- 멀티/방 생성 본문에 제목 아래 2cqh 여백을 둔다. 방 목록의 생성 버튼은 본문 우측, 생성 화면의 제출 버튼은 footer 중앙에 둔다. 뒤로가기는 좌상단 화살표로 통일한다.
- Chrome headless에서 1280×720 빈 목록, 800×540 방 6개 목록과 방 생성 화면을 확인했다. 타입 검사·프로덕션 빌드 통과. 크기와 여백만 수정했으며 기능 코드는 유지한다.

## 맵 선택 이미지·목표 배지 (2026-10-23)
- 멀티 방 생성과 맵 선택 팝업은 기존 배경 이미지를 16:9 비율의 큰 미리보기로 재사용한다. 높이 5/9cqh의 얇은 이미지 띠로 되돌리지 않는다. 대기방의 작은 맵 요약은 유지한다.
- 선택 카드 본문을 세로 flex로 구성하고 최소 높이를 내용 기준으로 계산한다. 이미지·설명·Finish/No falls/시간 목표가 모두 카드 안에 들어가도록 늘어나며, 좁은 화면에서는 배지가 줄바꿈된다. overflow로 배지를 잘라 숨기지 않는다.
- 목록 그리드는 내용 높이의 행을 사용하고 목록 전체가 스크롤된다. 방 생성의 최종 Create room 버튼은 footer 중앙, 뒤로가기는 좌상단 화살표에 배치한다. 방 목록 상단의 Create room 버튼은 유지한다.
- Chrome headless에서 1280×720 영어, 800×540 한국어·방 생성, 520×400 영어 화면을 확인했다. 모든 카드의 목표 배지 사각 영역이 카드 내부에 포함되고 scrollHeight/clientHeight가 일치함을 확인했다. 전체 197개 테스트·타입 검사·빌드 통과.

## 뒤로가기·맵 변경 통일 (2026-10-23, 이전 배치보다 우선)
- 싱글·멀티 목록·방 생성·멀티 대기방은 좌상단 ←를 공통 사용한다. 생성→멀티 목록→모드 선택 순서로 이전 단계에 이동하고, 싱글은 모드 선택으로 돌아간다. 모드 선택의 우상단 ×는 로비로 닫는다.
- 맵 선택 등 작은 팝업의 ×는 해당 팝업만 닫는다. 방 목록 Previous/Next/페이지는 footer 중앙을 유지하며 우하단 Back은 제거한다.
- 대기방의 ← 및 Leave는 방 나가기 확인창을 연다. Cancel/×/Escape는 방에 남고, 확인 시에만 기존 leave 명령을 보내 방 목록으로 돌아간다. 요청 중 중복 입력을 막고 취소·언어 변경·씬 종료 시 inert/포커스를 복구한다.
- ConfirmPopup은 기존 settings-panel/purchase-panel/action 스타일을 재사용한다. 확인 오버레이는 기본 메뉴(30)보다 높은 z-index 31에 둔다.
- 싱글 맵 정보 영역을 상단 정렬하고, 카드 우상단의 맵 이름 줄에 Change map (개수) ▾ / 맵 변경 (개수) ▾를 배치한다. Play는 하단 중앙을 유지한다.
- 전체 199개 테스트·타입 검사·빌드 통과. Chrome headless에서 PC/작은 가로 화면의 한영 싱글 화면, 멀티 목록, 실제로 메뉴 앞에 표시되는 방 나가기 확인창을 검증했다. 실제 계정 간 멀티 접속 검증을 의미하지 않는다.

- reduced-motion 설정에서는 버튼 전환과 기존 타이틀 안내 애니메이션을 줄인다. 픽셀 동물의 몸체 크기/동작/히트 영역과 플레이 조작은 변경하지 않는다.

## 폰트와 배포
- 공식 배포본: https://github.com/google/fonts/tree/main/ofl/jua 및 https://github.com/google/fonts/tree/main/ofl/gowundodum.
- 원본 TTF의 글리프를 삭제하지 않고 fontTools + Brotli로 WOFF2 형식만 변환했다.
- public/assets/fonts/Jua-Regular.woff2 368,836 bytes, GowunDodum-Regular.woff2 445,388 bytes. 대응 OFL 원문을 함께 배포한다. 다운로드/로컬 변환은 제작 단계 작업이며 npm/CI 추가 의존성은 없다.
- index.html에서 선로딩한다. CSS @font-face의 font-display:swap으로 지연/실패 시 대체 글꼴도 표시한다. 외부 폰트 서비스에 런타임 요청하지 않는다.
- Boot/Preload 문구를 DOM으로 표시해 웹폰트가 늦게 로드돼도 바뀌게 했다. 씬 종료 시 캡션을 제거하고, 기존 중복 로딩 문구 방지도 유지한다. 진행 막대는 Pixi Graphics를 사용한다.
- 스타일은 src/ui/cozy-theme.css에 모았으며 src/main.ts에서 기존 style.css 다음에 불러온다.

## 2026-10-19 로비 버튼
- 사용자 승인으로 로비 7개 메뉴의 그림과 표면 스타일만 변경했다. Character/Home 좌측, Quest/Friends/Shop/Settings 우측 상단, Play 우측 하단의 기존 배치를 따른다.
- 기존 인라인 SVG 아이콘을 직접 수정해 파스텔색 면·둥근 외곽선으로 통일했다. 아이콘 아래 한영 이름과 접근성 라벨을 유지한다. 새 이미지 생성·다운로드나 라이브러리 추가는 없다.
- 크림색 원형 바탕에 얇은 베이지 테두리, 안쪽 하이라이트와 낮은 그림자. Play는 더 큰 연두색 원형과 흰 재생 아이콘, 아래 크림색 이름으로 강조한다.
- 누르면 아이콘과 이름이 작게 내려가고 그림자가 줄어든다. 마우스 hover는 fine pointer에서만 적용하고 reduced-motion에서는 이동 효과를 끈다.
- 키보드 포커스를 원형 아이콘 테두리에 표시한다. 비활성은 채도/투명도를 낮추고 버튼 터치 영역은 최소 44px로 둔다. Quest 보상 알림과 공통 클릭음/씬 이동은 기존 흐름을 사용한다.
- Windows 브라우저 확인 도구가 커널 초기화 실패로 실행되지 않았다. 실제 모바일의 아이콘/라벨 크기와 화면상 간격은 사용자 확인이 필요하다.
- 검증: 기존 자동 테스트 114개·타입 검사·프로덕션 빌드 통과. 시각 변경 전용 테스트는 추가하지 않았다.

- 구매 영역을 하나의 바닥 영역으로 묶고 상품명·가격·구매 버튼을 함께 배치한다. Hat:1은 실제 상품명 산타모자/Santa Hat, 다른 프로토타입 상품은 기존 분류+번호를 사용한다.
- 버튼은 구매 가능(연두)/보유·구매 완료(옅은 녹색)/코인 부족(살구)/처리·조회 중(버터)/연결 확인 필요(회색)를 구분한다. 상태는 문구로도 표시하며 기존 비활성·서버 검증 규칙을 유지한다.
- 서버 재화 첫 조회 전에는 Coins: —로 표시하며, 로컬 기본값을 계정 잔액으로 보여주거나 기본 아이템을 보유한 것처럼 표시하지 않는다.
- 구매 요청과 서버 응답 중 목록의 스크롤 위치를 보존한다. 현재 선택 상품과 다른 상품의 응답이 도착해도 구매 완료 표시는 실제 구매한 분류/번호에만 붙인다.
- 한영 변경 시 화면을 다시 표시하고 언어 리스너를 씬 종료 시 해제한다. 기존 캐릭터 미리보기/구매 후 이모션/패스 테스트 해금 규칙은 유지한다.
- Shop 테스트에서 최초 조회·임시 잔액 숨김·보유/구매 가능/처리 중/구매 완료·스크롤 유지·중복 차감 방지를 검증한다. 실제 모바일 화면 배치와 터치 느낌은 별도 확인 대상이다.
- 최종 검증: 전체 114개 자동 테스트·타입 검사·프로덕션 빌드 통과. 새 SQL 적용은 필요하지 않다.
