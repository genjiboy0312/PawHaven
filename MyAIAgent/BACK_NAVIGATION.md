# 웹·PWA 뒤로가기

## 2026-11-06

- BackNavigation의 공통 설치 한 번과 backAction 등록으로 기존 닫기/복귀 동작을 사용한다. UI 루트는 WeakMap으로 연결하고 DOM에서 분리된 화면은 대상에서 제외한다.
- 현재 표시된 가장 뒤쪽 DOM 루트부터 처리한다. 숨긴 메뉴는 건너뛰며 처리 중 inert 상태는 뒤로가기를 소비하고 유지한다. 구매 확인은 기존 submitting 차단을 그대로 따른다.
- 설정·퀘스트·친구·우편함·구매·확인·조작 배치·맵 선택·공원 메뉴/프로필·모바일 텍스트 입력 등은 기존 닫기/취소로 연결했다. 복귀 안내는 기존 이어하기/방 목록 버튼의 동작을 사용한다.
- 캐릭터·홈·상점은 기존 X 경로를 사용한다. 캐릭터의 저장 대기/실패 처리를 우회하지 않는다. 친구 홈 방문은 방문 전 화면으로 돌아간다. 공원 채널 선택을 열었으면 먼저 선택창을 닫고, 초기 입장/공원에서는 기존 나가기 경로를 사용한다.
- 싱글 플레이에서는 설정창과 기존 중도 나가기 확인을 연다. 멀티 게임은 공통 확인창을 거쳐 기존 퇴장 콜백을 실행하며 취소 시 로컬 일시정지를 해제한다. 완주 결과는 기존 로비/대기방 복귀 버튼을 사용한다. 대기방은 기존 navigateBack/퇴장 확인을 재사용한다.
- URL을 바꾸지 않는 임시 history 가드 하나만 사용한다. 중첩 팝업마다 기록을 추가하지 않으며 기존 history.state 필드를 보존한다. 마지막 관리 화면을 닫으면 가드를 정리해 로비에서는 브라우저의 이전 페이지 이동을 허용한다. 새로고침 시 남은 가드도 인식해 중복 기록/뒤로가기 함정을 막는다.
- main에서 설치하고 일반 pagehide 및 HMR 종료 시 이벤트/MutationObserver를 정리한다. BFCache 복귀는 기존 게임 수명을 유지한다. DOM 텍스트만 바뀌는 게임 프레임에서는 전체 대상을 다시 조회하지 않는다.
- 공통 기록 모델과 기존 게임·멀티·공원·입력 회귀 검사 230개, 타입 검사·빌드 통과. Chrome 실제 기록에서 중첩 구매/설정/맵 닫기, 꾸미기 복귀, 싱글 확인·취소, 이전 페이지 복귀, 가드 상태 재로드를 확인했다. 구매 대기 유지와 서버 대역 대기방의 취소/퇴장 명령 한 번도 확인했다.
- Chrome 테스트는 데스크톱 브라우저 기록과 서버 대역을 사용했다. 실제 Android Chrome/삼성 인터넷/PWA 제스처 및 두 기기 멀티는 별도 검증이다. 키보드·전체화면은 브라우저가 뒤로가기를 먼저 처리할 수 있다. APK 네이티브 backButton 연결과 탭/앱 강제 종료 제어는 포함하지 않는다.
- 새 SQL·리소스·패키지는 없다.
