# 모바일 앱·브라우저 복귀 처리

## 범위 (2026-10-22)
- 기존 씬·팝업·RoomClient를 재사용한다. 새 이미지, 의존성, SQL은 추가하지 않는다.
- 싱글 플레이 중 visibilitychange(hidden) 또는 pagehide가 발생하면 입력을 비우고 별도 suspended 상태로 물리·기록 시간을 멈춘다.
- 돌아오면 공통 크림색 패널과 Continue / 이어하기 버튼을 표시한다. 자동으로 달리지 않으며 이전에 누른 키·조이스틱도 이어받지 않는다.
- Settings의 paused 상태와 복귀 suspended 상태를 분리한다. 설정이 이미 열렸다면 복귀 팝업은 설정을 닫은 뒤 표시한다. 완료된 싱글 결과창에는 팝업을 추가하지 않는다.
- RunRecoveryPopup은 표시와 HUD 입력 차단만 맡는다. PlayScene이 수명·게임 상태를 관리하고 종료 시 리스너와 팝업을 정리한다.

## 멀티
- 기존 RoomClient 옵저버·서버 sync·recoverySerial·위치 복원을 유지한다. 다른 플레이어의 경기는 앱을 나갔다고 멈추지 않는다.
- pagehide/visibilitychange에서 전송·구독을 중단하고 진행 중 요청을 abort한다. 오래된 응답은 기존 revision 검사로 무시한다. 복귀 시 서버 sync가 끝나기 전 조작과 mutation을 차단한다.
- 복귀 전 RTT/서버 시계 표본을 비워 현재 연결에서 다시 계산한다. Game은 pageshow에서도 렌더링 재시작 여부를 확인한다.
- 경기 중 복구가 20초 이상 걸리면 안내와 '방 목록으로' 버튼을 표시한다. 복구가 먼저 성공하면 팝업은 자동으로 사라진다. 버튼 클릭은 한 번만 처리하며 기존 클라이언트를 폐기하고 멀티 방 목록을 다시 연다.
- 퇴장은 기존 best-effort leave RPC를 사용한다. 오프라인에서는 즉시 서버 퇴장을 보장하지 않는다. 기존 서버는 다음 RPC 처리 시 45초 이상 heartbeat가 없는 참가자를 정리하고 방장을 위임한다. 서버가 살아 있는 기존 참가 상태를 반환하면 그 상태가 우선한다.
- 대기방은 기존 재연결 상태 안내·재시도 버튼·닫기를 재사용한다. 별도의 새 대기방 모달이나 자동 Ready 재전송은 추가하지 않는다.
- 기존 완주 ack 유실 후 sync로 확정 기록을 확인하는 처리를 유지하며 보상·완주를 복귀 이벤트에서 다시 호출하지 않는다.

## 검증
- 싱글 숨김 중 시간·좌표 정지, 입력 제거, 팝업 중복 방지, 설정과의 순서, 완료 후 보상 중복 금지, 종료 후 이벤트 정리.
- 멀티 20초 안내, 정상 복구 후 팝업 해제, 방 목록 이동 콜백 한 번 처리.
- pagehide로 진행 중 요청 취소, pageshow의 새 sync, 폐기 후 리스너 해제.
- 기존 방장 위임·만료 참가자·완주 ack 유실 테스트를 함께 유지한다.
- 모의 DOM/실제 로컬 SQL 테스트다. 실제 안드로이드 앱 전환·Wi-Fi 전환·운영 Supabase 두 기기는 별도 확인이 필요하다. OS가 페이지를 완전히 종료하면 메모리의 싱글 진행 상태는 유지되지 않는다.
