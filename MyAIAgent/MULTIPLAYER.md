# 모드 선택·멀티 레이스 프로토타입 (2026-10-19)

## 사용자 승인 범위
- Play → Single/Multiplayer. Single은 맵 선택 후 기존 코스 플레이.
- 방 목록은 한 페이지 2행×2열/4개, 가로 스와이프·스크롤 스냅·이전/다음·페이지 번호. 방 이름/맵/대기·진행 상태/인원 ? / 4 표시.
- 최대 4인 공개 방 생성·입장. 방장만 맵 선택, 방원 Ready/취소, 최소 2인+방원 전원 Ready 때 시작.
- 맵 변경 시 Ready 초기화. 진행 중 입장 금지. 방장 퇴장 시 먼저 입장한 생존 멤버로 이전.
- 3초 서버 시각 카운트다운, 서로 통과하는 레이스, 서버 순위, 결과 확인 후 같은 대기방 복귀.

## 서버 적용
1. 기존 계정/재화 migration이 적용된 Supabase SQL Editor에서 `supabase/migrations/202610190003_multiplayer.sql` 최종본 전체 실행.
2. 새 RPC를 확인하고 실제 서로 다른 Google 계정/기기로 방 생성→입장→Ready→Start→완주→복귀를 확인한다.
3. 적용 전 UI는 서버 준비 안내를 표시한다. 로컬 방/가짜 플레이어를 운영 화면에 만들어 실제 멀티처럼 보여주지 않는다.

새 테이블은 mp_rooms / mp_members / mp_racers. RLS 활성화, anon/authenticated의 직접 테이블 권한 없음. authenticated만 multiplayer_command를 실행하며 모든 명령은 auth.uid()로 실행자를 결정한다. 방 정보 조회도 로그인이 필요하다. 닉네임과 동물/착용 정보는 서버 프로필/저장/보유권에서 구성하며 이메일은 방에 노출하지 않는다.

서버에서 마지막 자리·한 계정의 한 방 가입·방장 권한·Ready·3초 출발·라운드 ID·완주 기록을 검증한다. 퇴장/45초 이상 heartbeat 없는 멤버를 정리하고 방장을 이전한다. 카운트다운 중 2명 미만이면 취소한다. 첫 완주 후 20초 또는 라운드 최대 120초가 지나면 결과로 전환한다. 전원 완주 시 다음 동기화에서 바로 결과로 이동한다. 결과를 확인한 사람은 대기방에서 기다리고, 모두 돌아오면 다음 Ready를 받을 수 있다.

## 재사용·연결
- PlayMenuPopup은 Settings의 모달·포커스/입력 차단·버튼 스타일과 기존 정원 이미지를 재사용한다.
- 맵은 CourseCatalog의 정원 산책길(20~30초)과 기존 연습 마당(8~12초). 새 아트/라이브러리를 추가하지 않는다.
- 싱글은 기존 경제 run_start/run_finish/퀘스트 흐름을 유지한다. 멀티 결과는 별도 서버 라운드이며 이번 버전에서 코인/XP/일일 완주 보상을 새로 지급하지 않는다.
- 멀티는 현재 서버 저장의 동물과 착용을 기준으로 표시한다. 입장/생성 전 보류된 꾸미기 저장을 시도한다. 다른 참가자는 기존 AnimalAnimationController/AnimalEffects와 이름 표시를 사용한다.
- RoomClient는 로그인 소유자의 토큰을 요청마다 고정하며 계정 전환/종료 뒤 이전 응답을 적용하지 않는다. 종료 시 방 퇴장을 시도하고 네트워크 실패는 heartbeat 만료로 정리한다.

## 동기화와 한계
- 별도 WebSocket 서버나 Realtime publication 설정 없이 RPC를 재사용한다. 대기/방 목록은 요청 완료 후 약 1.2초, 레이스/카운트다운은 약 0.3초 뒤 다음 요청을 보낸다. 동시에 요청을 겹쳐 보내지 않는다.
- 동작/위치는 저빈도 스냅샷과 화면 보간·짧은 수평 예측으로 표시한다. 서버는 인증된 본인 포즈만 갱신하고 좌표 범위를 제한하지만 물리/입력 자체는 클라이언트에서 계산한다.
- 멀티 기록은 서버 출발/접수 시각으로 정하며 최소 시간·피니시 위치·라운드를 확인한다. 이는 완전한 부정행위 방지가 아니다. 멀티 기록을 유료 재화/경쟁 보상 기준으로 쓰기 전에 서버 권위 시뮬레이션과 추가 검증이 필요하다.
- 전역 advisory lock을 사용하는 소규모 프로토타입이다. 활성 방/사용자 증가 전에는 방별 동시성 설계와 전용 실시간 전송을 검토해야 한다. 방 목록은 최근 80개를 표시한다.
- 창을 닫으면 즉시 종료를 보장하지 않고 45초 TTL로 정리한다. 앱 전환/느린 네트워크는 결과와 조작에 지연을 줄 수 있다. 게임 Settings는 해당 기기 입력만 멈추며 서버 레이스 시계와 다른 참가자는 계속 진행한다.
- 초기 서버 SQL 적용과 실기기 2~4인/네트워크 지연·재접속 검증은 자동 테스트와 구분한다.

## 검증
- PGlite 실제 SQL: 4인 제한/5번째 입장 거부, 비회원·직접 테이블·익명 RPC 차단, 방장 권한/Ready/맵 변경, 시작 후 입장 차단, 방장 이전·TTL 정리, 인증 사용자 포즈 귀속, 오래된 라운드/잘못된 피니시 거부, 기록 중복 보호, 결과/대기방 복귀, 카운트다운 인원 감소 취소.
- UI/클라이언트: 4개씩 2×2 페이지·인원수·진행/가득 찬 방 차단, 실제 SQL 스냅샷 기반 Start 조건·모달 정리, 카운트다운 이동 차단·상대 표시/애니메이션·결과 후 복귀, 소유자 토큰 고정·늦은 응답 무시, 게스트 싱글 맵 선택, 중복 폴링 차단.
- 전체 125개 테스트와 타입 검사/프로덕션 빌드를 실행한다. 실제 Google 계정 2개로 접속하는 모바일 시각·멀티 플레이는 별도 확인 대상이다.
