# 2D 조작 UI·멀티 패널·상점 헤더 적용

## 조작부
- 승인된 Resources/Touch_Controls_UI_Prototype_v3.png를 기준으로 평면 원형 색면·갈색 외곽선·얕은 그림자를 적용했다. Attack은 발바닥만, Dash는 이중 화살표, Jump는 위 화살표다.
- 이미지 시안 v1/v2/v3는 Resources에 모두 보존한다. 실제 아이콘은 직접 작성한 단순 SVG를 Resources/Control_Attack.svg, Control_Dash.svg, Control_Jump.svg에 저장하고 public/assets/controls에 동일 파일을 배포한다. 시안 전체 PNG를 잘라 붙이거나 무거운 텍스처를 추가하지 않는다.
- 기존 발바닥 배치·큰 Jump·좌측 조이스틱·왼손잡이 옵션·조작 크기·키보드 입력을 유지한다. 조이스틱은 반투명 평면 바닥·크림색 손잡이와 좌우 방향 표시를 사용한다.
- ActionButton이 아이콘·번역 라벨·쿨다운 표시를 담당하고 PlayScene의 기존 업데이트에서 상태를 전달한다. 라벨만 번역하므로 아이콘이 텍스트 변경으로 지워지지 않는다. 별도의 타이머·옵저버·네트워크 요청은 없다.
- DummyRun.canJump/canDash/canAttack을 실제 행동과 UI가 함께 사용한다. 규칙과 속도는 유지한다: 공중 대시 금지, 공중 공격 허용, 대시 중 공격/점프 제한, 공격 중 대시 제한. 대시 쿨다운은 기존 0.8초다.
- 대시 테두리 원호가 차오르고 남은 시간을 0.1초 단위로 표시한다. 사용 불가·일시정지·출발 대기에는 실제 버튼을 비활성화한다. 포커스 표시와 reduced-motion 설정을 유지한다.

## 멀티 패널
- 방 만들기 버튼에 일관된 너비·높이와 box-sizing을 적용하고 상단 우측에 맞췄다.
- Previous / Next / 페이지 숫자 / Back을 스크롤 본문 밖의 footer로 옮겼다. 목록만 스크롤하며 페이지 이동과 뒤로 버튼은 패널 하단에 남는다. 페이지 이동은 중앙, Back은 우측이다.
- footer도 기존 busy/재접속 잠금에 포함하고 Back의 복구 중 이동 허용 규칙을 유지한다. 싱글 선택 화면은 기존 좌측 상단 뒤로 버튼을 유지한다.

## 상점
- 제목·코인 잔액·X의 높이와 상단 기준선을 맞췄다. 코인은 X 왼쪽에 간격을 두고 배치한다.
- 헤더 높이와 탭 높이로 상품 영역의 시작 위치를 계산해 작은 가로 화면에서도 겹치지 않게 한다. DOM·구매 확인·재화·소유권·탭 동작은 유지한다.

## 검증
- 전체 테스트 192개·타입 검사·프로덕션 빌드 통과. 실제 입력 제한·공중 공격·쿨다운·일시정지·한영 아이콘 유지, 리소스 원본/배포본 일치, 하단 페이지 이동과 뒤로 동작을 검증한다.
- Chrome headless로 실제 모듈·CSS·폰트를 불러온 임시 UI fixture를 렌더링했다. 멀티 footer가 본문 아래에 분리되고, 작은 가로 창에서 코인/X의 y·높이가 같으며 탭 끝보다 상품 시작이 아래임을 확인했다. 버튼 색·아이콘·배치도 이미지로 확인했다. fixture는 모의 방/빈 캐릭터 프리뷰이며 실제 로그인·멀티 접속 테스트는 아니다.
- 임시 fixture·로그는 정리하고 로컬 서버를 종료한다. 실제 모바일 터치감·두 기기 멀티는 별도 확인 대상이다. SQL·추가 의존성은 없다.
